## 高优偏离

### H1. 全篇无 Markdown 标题(`#` `##` ...)
- 现象: 11 个文件均无任何 `#` 起始行,所有"节标题"被错位表达为以下两种之一:
  1. 编号列表(数字小标题): `1. **声明变量**` / `1. **创建数组**` / `1. **定义**` / `1. **List****集合**` / `1. **import kotlin.math.***` / `1. kotlin中的数字的**内置类型**`
  2. 代码块包裹的伪标题: ` ```kotlin\n**类的定义**\n``` ` / ` ```kotlin\n**函数的创建与使用**\n``` ` / ` ```kotlin\n**封装**\n``` ` / ` ```kotlin\n**数据类型**\n``` ` 等
- 影响文件: 全 11 篇
- 后果: 文档无目录(结构化大纲)、搜索与 TOC 工具识别不到节标题、Obsidian 大纲视图为空

- `程序设计中级/类与对象.md` 第 181-207 行优先级表(同样模式): 4 列被代码块打断

## 中优偏离

### M1. 代码块内仍残留不必要的反斜杠转义
用户报告"反斜杠转义 ✅",但实际在 kotlin 代码块内仍存在:
- `程序设计中级/函数.md`: 无
- `程序设计中级/封装，继承和多态.md`: `-\>` ×4、`\<T\>` ×4(出现于 ` ```kotlin ` ` ```xml ` 块内)
- `程序设计中级/类与对象.md`: `\>` ×2(`a.compareTo(b) \> 0`)、`\<` ×2,均在 `kotlin` 代码块内
- `基础/基础语法.md`: 11 处 `-\>`(第 49-77 行 kotlin 块内), 3 处 `\<...\>` 在 `xml` 块内(第 33-35)
- `程序设计高级/泛型.md`: 4 处 `\<...\>`、4 处 `-\>`(均位于 `xml` 块内)

判定: `\<` `\>` 在 `xml` 块中合法(实际表现同 `&lt;` `&gt;`),可保留;但 `kotlin` 代码块内的 `-\>` 应保持 `->`、`score\>60` 应保持 `>`、`compareTo(b) \> 0` 应保持 `>`。建议清理场景限于 kotlin/xml 两种语言块各自保留合规转义。

### M2. 全角 / 半角标点混用
- 半角括号包裹全角括号: `基础/基础语法.md:49` `if(score\>60）"Yes"` → 同行的 `(` 是半角,`）` 是全角,需统一

- `程序设计中级/封装，继承和多态.md` 第 21,33-34,42,52,59,73,77 等 多个 `,` 与 `，` 在同一行混用
- `程序设计高级/集合.md` 大面积使用 `，` `：` `（）`,与英文 `,` `:()` 大量穿插
- `程序设计中级/类与对象.md` 中文标点密度极高,与英文标点并存(描述性文本中:用全角;代码中:用半角,但混用)

## 自动修复可行性

### 完全可自动(X 类)
- **X1**: 给所有 ` ```kotlin\n**xxx**\n``` ` 形式的伪标题,转换为 `## xxx`
- **X2**: 给所有 ` ```xml\n**xxx**\n``` ` 同样处理(若确认该处是标题)
- **X3**: 把编号列表 `N. **xxx**` (N 通常是 1) 提取为 `## xxx`,再清掉 `N.`
- **X4**: 将 kotlin 代码块内的 `-\>` / `\>` / `\<` 替换为 `->` / `>` / `<`(xml 块内的 `\<` `\>` 保留)
- **X5**: `&nbsp;` → 真实空格
- **X6**: `pulsAssign` → `plusAssign`、`peintln` → `println`、`arrry` → `array`、`indexs` → `indices`、`intArrayOF` → `intArrayOf`、`takeLsat` → `takeLast`、`mutableMapOF` → `mutableMapOf`(注意大小写一致性)
- **X7**: 给 `类与对象.md` `函数.md` `数组.md` `集合.md` `特殊类型.md` `封装，继承和多态.md` 裸文 Kotlin 块外包 ` ```kotlin ` ` ``` `
- **X8**: 删除孤立单字符 `}` 浮行(先做语法保护:仅删除"段首 / 段尾 / 自身一行"的 `}`)

### 需人工判断(Y 类)
- **Y1**: `类与对象.md` 三张运算符表 / `封装，继承和多态.md` 扩展函数表 的"代码块塞表格"修复: 需要确认每行 4/8 列应有的实际内容才能决定如何把代码块合并回单元格
- **Y2**: 编号列表跳号:是按原稿语义补回(2,3,4 …),还是改造为不带数字的 `##`-级标题(取决于阅读器期望)
- **Y3**: 中文 / 英文标点在代码块内:统一为半角更正确,但部分笔记可能希望保留中文标点,需要按目录/笔记风格统一一份"目录级 Punctuation policy"
- **Y4**: `特殊类型.md` 第 1 行 `1. ``` ` 这种结构,如果语义是"第 1 节:数据类型",则应改为 `## 数据类型`,并把下面 3 条 `- ...` 提到顶格(取消缩进)

### 不可自动(Z 类)
- **Z1**: 跨多文件的章节归属:目前文件名为章节名(类与对象、函数…),但每个文件内的"小节标题"用伪标题表示,难以 100% 判断应当映射到哪一个 h2 还是 h3
- **Z2**: `封装，继承和多态.md` 文件名含有中文逗号 `,`(原 OneNote 标题),如需迁移需用户决定保留还是替换
- **Z3**: 代码块内 inline 强调标记 `**xxx**` 的去除:在 kotlin 块里 `**顶层变量**` 等应当仅作为字面文本出现(`**` 不会渲染但字面存在),这类语义"本意是标题但放在代码块内"需人工识别每一个位置

## 推荐处理顺序

1. **先建标题骨架(X1+X2+X3)**: 把所有编号列表/代码块伪标题一次性抽取成 `## h2`,这样后续预览/搜索均有锚点
2. **修复表格骨架(H3+H4)**: 对 `类与对象.md`、`封装，继承和多态.md` 三张运算符表合并回"单格多行代码块"的写法(GFM 支持在格内嵌入 ` \`\`\`kotlin ` … ` \`\`\` `);`基础知识.md` 的 42 个栅栏则应合并为一行多列或多个多行代码块
3. **包裹裸文 Kotlin(X7)**: 给 `函数.md`、`数组.md` 三大块未包裹的 Kotlin 文本裹上 ` ```kotlin `
4. **修正拼写类小错(X6)**: 一次性 sed 替换 `pulsAssign` / `peintln` / `arrry` / `indexs` / `intArrayOF` / `mutableMapOF` / `takeLsat`
5. **归一标点(Y3)**:按目录草拟"代码块内一律半角 / 描述文本一律中文全角"政策,然后执行
6. **处理编号跳号(Y2)**: 与步骤 1 同时完成;跳号项直接并入"标题抽取"分支
7. **处理 `特殊类型.md` 列表嵌入栅栏(Y4)** 单文件特殊处理:把第 1 行 `1. ``` ` 整体改写为 `## 数据类型`
8. **孤立 `}` 漂浮行(X8)**: 最后做一遍正则清理
9. **目录级标题映射(Z1)**: 由人按主题整理 h2 → h3 层级

## 关键风险

- 一旦执行 X1+X2+X3,原始"伪标题"上下文会丢失。建议在落盘前用 `git diff` 或备份对照原 OneNote 截图。
- H4 中 42 个栅栏在 `基础知识.md` 中承载了真实 Kotlin 语句,合并需保留全部内容,不可仅取首个非空行。
- 类与对象.md 多张表格若按"逐格并入代码块"修复,需保证 GFM 表格列数与表头列数严格匹配(8 列),否则新表也会失效。
