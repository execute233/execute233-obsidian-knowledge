# LangGraph 核心概念与故障排查

## 核心概念速查

| 概念                       | 一句话理解                                |
| ------------------------ | ------------------------------------ |
| `StateGraph`             | 定义共享 State 和执行图的构建器                  |
| State                    | 节点之间共享的数据                            |
| Node                     | `State -> PartialState` 的执行函数        |
| Edge                     | 节点之间的固定跳转                            |
| Conditional Edge         | 通过路由函数选择下一节点                         |
| Reducer                  | 决定 State 字段如何合并                      |
| `MessagesState`          | 内置 `messages + add_messages` 的 State |
| `ToolNode`               | 执行模型请求的工具调用                          |
| `tools_condition`        | 有工具调用则去 tools，否则结束                   |
| Checkpointer             | 保存 thread 内 Graph 状态                 |
| Store                    | 保存跨 thread 长期数据                      |
| `thread_id`              | 一段持久会话的定位键                           |
| `interrupt()`            | 暂停 Graph，等待外部输入                      |
| `Command(resume=...)`    | 恢复被中断的 Graph                         |
| `Command(update, goto)`  | 同时更新 State 并动态跳转                     |
| `Send`                   | 动态创建多个 Worker 任务                     |
| Subgraph                 | 作为父图节点运行的另一张 Graph                   |
| `stream_mode="messages"` | 输出 LLM Token                         |
| `stream_mode="updates"`  | 输出节点局部更新                             |
| `RetryPolicy`            | 节点失败后的重试规则                           |
| `TimeoutPolicy`          | 单次节点尝试的超时规则                          |
| `recursion_limit`        | 整张 Graph 的最大执行步数                     |

## 设计原则

1. **确定性逻辑使用普通代码，开放式判断再交给 LLM。**
2. **节点返回局部更新，不要无意义地返回整个 State。**
3. **消息字段使用 Reducer，普通字段按业务选择覆盖或聚合。**
4. **工具描述和参数 Schema 决定模型是否能正确调用工具。**
5. **启用 Checkpointer 后，每轮只提交本轮新增消息。**
6. **`thread_id` 负责定位状态，但不负责权限验证。**
7. **不可逆副作用放到人工审批之后，并保证幂等。**
8. **并行 Worker 写同一字段时必须配置 Reducer。**
9. **不要从同一节点同时混用普通边和动态路由。**
10. **生产系统要设置重试、超时、循环上限、日志和保留策略。**

## 常见故障定位

| 现象 | 优先检查 |
|---|---|
| 节点没有运行 | 是否注册节点、是否有边通向它 |
| `KeyError` | 字段是否在之前节点生成 |
| 消息历史丢失 | 是否使用 `MessagesState` 或 `add_messages` |
| 消息重复 | 是否手动返回了完整历史 |
| 第二轮不记得第一轮 | 是否配置 Checkpointer 和相同 `thread_id` |
| 所有用户共享历史 | 是否错误复用了同一个 `thread_id` |
| 工具从不调用 | 模型是否支持工具调用、Schema 和提示是否明确 |
| 工具执行后没有最终回答 | 是否存在 `tools -> agent` 边 |
| Graph 无限循环 | 路由退出条件、`recursion_limit` |
| 并行写入报错 | 共享字段是否配置 Reducer |
| interrupt 无法恢复 | 是否有 Checkpointer、是否使用同一 `thread_id` |
| 审批恢复后操作执行两次 | interrupt 前是否存在非幂等副作用 |
| 流式回答重复 | 是否同时渲染了 Token 和完整 AIMessage |
| 重启后会话消失 | 是否仍使用 `InMemorySaver` |
| 子图状态混乱 | State 映射、命名空间、持久化模式和并行调用 |
