# 结构型

## 适配器模式

使用一个类继承多个类/接口来满足不同的需求。

## 桥接模式

由于 Java 中没有多继承，可使用封装通过方法调用的方式来实现需求。

## 组合模式

对多维数据的封装。比如一杯奶茶，有类型、冷热、大小，这些属性都可以被封装，在构造时传入数据。

组合模式实际上就是将多个组件进行组合，让用户可以对它们进行一致性处理。比如我们的文件夹，文件夹中可以有很多个文件：

组合模式的示例如下，这里我们就用文件和文件夹的例子来讲解：

```java
/**
 * 首先创建一个组件抽象，组件可以包含组件，组件有自己的业务方法
 */
public abstract class Component {
    public abstract void addComponent(Component component);   // 添加子组件
    public abstract void removeComponent(Component component);    // 删除子组件
    public abstract Component getChild(int index);   // 获取子组件
    public abstract void test();   // 执行对应的业务方法，比如修改文件名称
}
```

## 装饰模式

通过封装或者继承的方式，让指定的类有更多的行为。

当有一个抽象时（A），有多个类（B、C… extends A）时，可使用额外的代理类（Proxy extends A）中的构造方法传入子类（? extends A），同样重写抽象类（A）的方法，但是方法都交由 ? 实现，其中可以进行装饰。

## 代理模式

当要使用多个类的方法时，要一个个地跑流程，这些流程可以封装到一个类中。

## 外观模式

我们可以将那些重复出现的内容作为共享部分取出，这样当我们拥有大量对象时，我们把其中共同的部分抽取出来，由于提取的部分是多个对象共享只有一份，那么就可以减轻内存的压力。

## 享元模式

享元模式通过共享已经创建的对象来减少内存使用。它将对象的内部状态（共享的、不变的）与外部状态（每个对象独有的）分离，使得相同的内部状态可以被多个对象共享。
