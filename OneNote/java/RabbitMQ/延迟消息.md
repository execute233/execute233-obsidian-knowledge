# 延迟消息

生产者发送消息时指定一个时间,消费者不会立刻收到消息,而是在指定时间之后才收到消息。

前置: [[RabbitMQ基础]] 介绍消息模式,[[可靠性]] 介绍消息持久化。

## 死信交换机

当队列满足下列情况之一时,就会成为死信:

- 消费者使用 `basic.reject` 或 `basic.nack` 声明消费失败,并且 `requeue` 参数为 `false`。
- 消息是一个过期消息(达到了队列或消息设置的过期时间),超时无人消费。
- 要投递的队列消息堆积满了,最早的消息可能成为死信。

队列通过 `dead-letter-exchange` 指定了交换机,那么该队列中的死信会投递到这个交换机中。该交换机成为**死信交换机(DLX)**。

发送消息指定 `expiration` 参数即可设置消息的过期时间(毫秒)。

![[_assets/延迟消息/延迟消息__09-22-55-0.png]]

```
publisher (TTL=30s)
    └─▶ simple.direct ──▶ simple.queue
                              │ (TTL 到期成为死信)
                              └─▶ dlx.direct (dead-letter-exchange)
                                       └─▶ dlx.queue ──▶ consumer
```

## 延迟消息插件

当消息投递到交换机后可以暂存一定时间,到期后再投递到队列。下载相关插件放在 plugins 目录后启用:

```bash
rabbitmq-plugins enable rabbitmq_delayed_message_exchange
```

然后就可以配置延迟交换机:

```java
@Bean
public DirectExchange delayExchange() {
    return ExchangeBuilder
        .directExchange("delay.direct")
        .delayed()      // 设置 delay 的属性为 true
        .durable(true)  // 持久化
        .build();
}

@RabbitListener(bindings = @QueueBinding(
    value = @Queue(name = "delay.queue", durable = "true"),
    exchange = @Exchange(name = "delay.direct", delayed = "true"),
    key = "delay"
))
public void listenDelayMessage(String msg) {
    log.info("接收到 delay.queue 的延迟消息:{}", msg);
}
```

发送消息需要通过消息头 `x-delay` 来设置过期时间,Java 代码里可以:

```java
template.convertAndSend("1", "mysql.1", "hello world!", message -> {
    message.getMessageProperties().setDelayLong(30000L);
    return message;
});
```

## 取消超时订单

### 存在问题

- 如果并发较高,堆积消息多会让 MQ 压力大。
- 大多数订单在下单后 1min 内支付,但是在 MQ 要 30min,浪费资源。

### 优化思路(阶梯式延迟)

![[_assets/延迟消息/延迟消息__09-23-02-2.png]]

下单 → MQ 延迟 30 分钟 → 收到消息查询订单状态(若已支付则结束,否则取消订单)。

优化:发送不同延迟时间的消息(阶梯重试),如 10s / 10s / 10s / 15s / 15s / 30s / 30s / 60s / 60s / 2m / 5m / 10m / 10m,在每档延迟后检查订单支付状态,若未支付则重发延迟消息。

![[_assets/延迟消息/延迟消息__09-23-04-3.png]]

**下单业务**:

- 开始 → 创建订单 → 发送延迟消息 → 结束。

**延迟消息处理**:

- 开始 → 查询支付状态 →(已支付 → 标记为已支付 → 结束;未支付 → 获取下次延迟时间 →(有延迟时间 → 重发延迟消息;无延迟时间 → 取消订单 → 恢复库存 → 结束)。
