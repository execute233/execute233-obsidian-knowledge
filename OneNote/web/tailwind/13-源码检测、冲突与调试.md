# 源码检测、冲突与调试

## 13.1 扫描器并不解析你的程序

Tailwind 将源码当作纯文本，查找看起来像类名的 token，再尝试生成匹配的 CSS；它不会执行 TypeScript，也不会理解字符串插值。[Detecting classes in source files](https://tailwindcss.com/docs/detecting-classes-in-source-files)明确说明了这一点。

错误：

~~~vue
<script setup lang="ts">
defineProps<{ color: string }>()
</script>

<template>
  <div :class="'bg-' + color + '-600'"></div>
</template>
~~~

正确：

~~~vue
<script setup lang="ts">
type Color = "blue" | "red"

const props = defineProps<{
  color: Color
}>()

const colorClasses: Record<Color, string> = {
  blue: "bg-blue-600 hover:bg-blue-500",
  red: "bg-red-600 hover:bg-red-500",
}
</script>

<template>
  <div :class="colorClasses[props.color]"></div>
</template>
~~~

## 13.2 默认扫描与忽略

v4 会自动发现项目源码，但默认忽略：

- <code>.gitignore</code> 中的文件。
- <code>node_modules</code>。
- 图片、视频、压缩包等二进制文件。
- CSS 文件。
- 常见 lockfile。

外部 UI 包包含 Tailwind 类名时，显式注册：

~~~css
@import "tailwindcss";
@source "../node_modules/@acmecorp/ui-lib";
~~~

monorepo 中明确基准目录：

~~~css
@import "tailwindcss" source("../src");
~~~

忽略已知目录：

~~~css
@source not "../src/components/legacy";
~~~

完全关闭自动检测并手动声明：

~~~css
@import "tailwindcss" source(none);
@source "../admin";
@source "../shared";
~~~

## 13.3 Safelist

确实无法让类名完整出现在内容文件时，可强制生成：

~~~css
@source inline("underline");
@source inline("{hover:,focus:,}underline");
@source inline("{hover:,}bg-red-{50,{100..900..100},950}");
~~~

也可明确排除：

~~~css
@source not inline("{hover:,focus:,}bg-red-{50,{100..900..100},950}");
~~~

Safelist 是最后手段。对于可枚举的 Vue props，静态映射通常更清晰、类型更安全。

## 13.4 类名书写顺序不解决冲突

~~~html
<div class="grid flex"></div>
~~~

不能仅凭“flex 写在后面”判断最终 display。实际由编译后 CSS 规则顺序决定。正确修复是只保留一个真实状态：

~~~vue
<div :class="gridLayout ? 'grid' : 'flex'"></div>
~~~

实在需要提高优先级时，v4 important 位于末尾：

~~~html
<div class="bg-red-500!"></div>
~~~

但优先排查：

- 是否同时传入了冲突 utility。
- 是否有 scoped CSS、第三方 CSS 或更高 specificity。
- 是否样式表导入顺序错误。
- 是否某个父元素或伪状态才是真正命中的规则。

## 13.5 “类名不生效”十步清单

1. 全局 CSS 是否真的被应用入口导入？
2. CSS 中是否有 <code>@import "tailwindcss";</code>？
3. Vite 配置是否包含 <code>tailwindcss()</code>？
4. 类名是否为官方支持的正确语法？
5. 类名是否以完整静态字符串出现在可扫描源码中？
6. 文件是否在 <code>.gitignore</code>、<code>node_modules</code> 或扫描范围之外？
7. DevTools 的 Styles 面板中，规则是不存在，还是存在但被覆盖？
8. variant 条件是否真的成立，例如 <code>md</code>、<code>hover</code>、<code>dark</code>？
9. 是否受到 Preflight 或第三方 CSS 影响？
10. 所用 utility 是否依赖目标浏览器尚未支持的现代特性？

判断分支：

~~~text
生成 CSS 中找不到规则
  → 扫描范围、动态拼接、类名拼写、构建配置

能找到规则但被划掉
  → specificity、layer、导入顺序、冲突 utility

规则命中但视觉没变化
  → CSS 布局上下文、继承、stacking context、浏览器支持
~~~

## 13.6 Preflight 排错

常见现象：

| 现象 | 可能原因 |
|---|---|
| h1 没有默认大字号 | Preflight 重置标题 |
| 列表没有圆点 | 列表默认样式被重置 |
| button 光标不是 pointer | v4 与浏览器默认一致，需显式 cursor |
| dialog 不再自动居中 | v4 Preflight 重置 margin |
| 第三方地图边框异常 | 全局 border reset |

应写最小、有作用域的覆盖，别轻易禁用整套 Preflight。

## 13.7 构建与验证

~~~bash
npm run build
~~~

至少检查：

- 构建无 unknown utility 错误。
- 生产 CSS 被正确输出。
- 页面各断点无横向意外溢出。
- dark / light / system 都可用。
- 键盘焦点、disabled、loading 状态可辨识。
- reduced motion 下功能完整。
- DevTools 中不存在大量互相冲突的 utility。
