# 容器与镜像

## 初识容器与镜像

将某个镜像从仓库下载到本地，可以：

```bash
docker pull hello-world
```

一个镜像是有 reposity 和 tag，一般约定前者是镜像名称，后者是版本（默认为 latest）：

```bash
docker pull 名称:版本
```

查看本地的镜像：

```bash
docker images
```

镜像下载后会存放在本地，启动一个本地的镜像可以：

```bash
docker run hello-world
```

如果只想创建而不是马上运行的话可以：

```bash
docker create hello-world
```

当镜像启动后会使用当前镜像自动创建一个容器，可以查看容器列表：

```bash
docker ps -a
```

可以手动指定名称启动，在 run 时：

```bash
docker run --name=name hello-world
```

可以手动开启处于停止状态的容器：

```bash
docker start/stop/restart <容器名称/容器ID>
```

删除容器（只能是非运行状态）：

```bash
docker rm <容器名称/容器ID>
```

删除镜像：

```bash
docker rmi <reposity_name>
```

## 镜像结构介绍

我们在打包项目时，实际上往往需要一个基本的操作系统环境，这样我们才可以在这个操作系统上安装各种依赖软件，比如数据库、缓存，像这种基本的系统镜像，我们称为 base 镜像，我们的项目之后都会基于 base 镜像进行打包，当然也可以不需要 base 镜像，仅仅是基于当前操作系统去执行简单的命令，比如我们之前使用的 hello-world 就是。

我们可以使用 `docker pull ubuntu` 的方式下载系统镜像，但这种镜像非常小。

Linux 操作体系由内核空间和用户空间组成，其中内核空间就是整个 Linux 系统的核心，Linux 启动后首先会加载 bootfs 文件系统，加载完成后会自动卸载掉，之后会加载用户空间的文件系统，这一层是我们自己可以进行操作的部分。

bootfs/rootfs 这套分层思想与 [[liunx/基础知识/文件系统|文件系统]] 是一致的：内核空间只读，用户空间可写，容器镜像本质上就是 rootfs 的打包。

- bootfs 包含了 BootLoader 和 Linux 内核，用户是不能对这层作任何修改的，在内核启动之后，bootfs 会自动卸载。
- rootfs 则包含了系统上的常见的目录结构，包括 /dev、/proc、/bin 等等以及一些基本的文件和命令，也就是我们进入系统之后能够操作的整个文件系统，包括我们在 Ubuntu 下使用的 apt 和 CentOS 下使用的 yum，都是用户空间上的。

base 镜像底层会直接使用宿主主机的内核，也就是说你的 Ubuntu 内核版本是多少，那么 base 镜像中的内核版本就是多少，而 rootfs 则可以在不同的容器中运行多种不同的版本。所以，base 镜像实际上只有 CentOS 的 rootfs。

对于直接启动相应的镜像，由于没有东西执行会立即退出，可以新建一个终端：

```bash
docker run -it ubuntu
```

要让终端保持运行，按住 `ctrl+p+q`，也可以附加回到指定容器：

```bash
docker attach <容器ID>
```

可以启动时进入到终端：

```bash
docker start -i <容器ID>
```

已经运行的容器，要新建一个终端：

```bash
docker exec -it <容器ID> bash
```

自动后台运行：

```bash
docker run -d xxx
```

每安装一个软件，就在 base 镜像上一层层叠加上去，采用的是一种分层的结构，这样多个容器都可以将这些不同的层次自由拼装，比如现在好几个容器都需要使用 CentOS 的 base 镜像，而上面运行的软件不同，此时分层结构就很爽了，我们只需要在本地保存一份 base 镜像，就可以给多个不同的容器拼装使用。

最上层是一个可写容器层：

所有的镜像会叠起来组成一个统一的文件系统，如果不同层中存在相同位置的文件，那么上层的会覆盖掉下层的文件，最终我们看到的是一个叠加之后的文件系统。当我们需要修改容器中的文件时，实际上并不会对镜像进行直接修改，而是在最顶上的容器层（最上面一般称为容器层，下面都是镜像层）进行修改，不会影响到下面的镜像，否则镜像就很难实现多个容器共享了。所以各个操作如下：

- **文件读取**：要读取一个文件，docker 会最上层往下依次寻找，找到后则打开文件。
- **文件创建和修改**：创建新文件会直接添加到容器层中，修改文件会从上往下依次寻找各个镜像中的文件，如果找到，则将其复制到容器层，再进行修改。
- **删除文件**：删除文件也会从上往下依次寻找各个镜像中的文件，一旦找到，并不会直接删除镜像中的文件，而是在容器层标记这个删除操作。

## 构建镜像

将镜像保存为文件：

```bash
docker save -o xxx.tar 镜像名:版本
```

基于 dockerfile 的形式创建镜像（推荐）：

我们可以新建一个 dockerfile 的文件：

```bash
touch dockerfile
```

然后编辑，里面需要多条指令来告诉 docker 镜像相关信息，下面是选择当前镜像的基础镜像：

```dockerfile
FROM <基础镜像>
```

需要用到 RUN 命令，在容器中运行命令，如：

```dockerfile
RUN apt update
RUN apt install -y openjdk-8-jdk
```

于是就编写完成了，只需要完成一次构建即可：

```bash
docker build -t <镜像名称> <构建目录（dockerfile 在哪就是哪）>
```

commit 创建（具有历史）：

```bash
docker commit -m "描述" -a "作者" 容器id 镜像名:版本
```

扁平化镜像：

```bash
docker export <容器ID或名称> > container-flat.tar
cat container-flat.tar | docker import \
  -c 'CMD ["/bin/bash"]' \
  -c 'ENV APP_ENV=production' \
  -m "描述信息" \
  -
```

## 发布到远程仓库

[Docker Hub](https://hub.docker.com/repositories)。

需要手动在网站上建仓库，结果一般是「个人名字/镜像名」。

需要修改镜像的 tag，可以：

```bash
docker tag 原名称:原标签（刚生成一般是 latest） 个人名字/镜像名:版本
```

需要在终端登录 docker：

```bash
docker login -u username
```

然后就可以上传：

```bash
docker push 个人名字/镜像名称:版本
```

注意公共镜像是可以下载的，我们可以把本地镜像全部删掉，去下载上传的镜像，我们可以先搜索：

```bash
docker search 个人名字/镜像名
```

然后就可以下载：

```bash
docker pull 个人名字/镜像名
```

## 案例：使用 IDEA 打包 SpringBoot 镜像

可以在 IDEA 上配置 docker 服务器，首先让服务端的 docker 允许远程访问：

```bash
vim /etc/systemd/system/multi-user.target.wants/docker.service
```

打开后，在 `ExecStart=` 这一行末尾添加 `-H tcp://0.0.0.0 --containerd=/run/containerd/containerd.sock`：

```ini
Type=notify
# the default is not to use systemd for cgroups because the delegate issues still
# exists and systemd currently does not support the cgroup feature set required
# for containers run by docker
ExecStart=/usr/bin/dockerd -H fd:// -H tcp://0.0.0.0 --containerd=/run/containerd/containerd.sock
ExecReload=/bin/kill -s HUP $MAINPID
TimeoutSec=0
RestartSec=2
Restart=always
```

修改完成后重启 docker，云服务器记得打开 2375 TCP 端口：

```bash
systemctl daemon-reload
systemctl restart docker.service
```

然后在 IDEA 配置远程，填 `tcp://host:ip`。

dockerfile 可以这样写，首先构建 app.jar，然后：

```dockerfile
FROM ubuntu
RUN apt update && apt install -y openjdk-25-jdk
COPY target/app.jar app.jar
CMD java -jar app.jar    # 可以设定容器启动后执行的命令
EXPOSE 8080              # 指定容器暴露的端口
```
