**初识容器与镜像**  
将某个镜像从仓库下载到本地，可以：  
docker pull hello-world  
一个镜像是有reposity和tag，一般约定前者是镜像名称，后者是版本（默认为latest）  
docker pull 名称:版本  
查看本地的镜像  
docker images  
镜像下载后会存放在本地，启动一个本地的镜像可以  
docker run hello-world  
如果只想创建而不是马上运行的话可以  
docker create hello-world  
当镜像启动后会使用当前镜像自动创建一个容器，可以查看容器列表  
docker ps -a  
可以手动指定名称启动，在run时  
docker run --name=name hello-world  
可以手动开启处于停止状态的容器  
docker start/stop/restart \<容器名称/容器ID\>  
删除容器（只能是非运行状态）  
docker rm \<容器名称/容器ID\>  
删除镜像  
docker rmi \<reposity_name\>  
**镜像结构介绍**  
我们在打包项目时，实际上往往需要一个基本的操作系统环境，这样我们才可以在这个操作系统上安装各种依赖软件，比如数据库、缓存，像这种基本的系统镜像，我们称为base镜像，我们的项目之后都会基于base镜像进行打包，当然也可以不需要base镜像，仅仅是基于当前操作系统去执行简单的命令，比如我们之前使用的hello-world就是。  
我们可以使用docker pull ubuntu的方式下载系统镜像，但这种镜像非常小  
Linux操作体系由内核空间和用户空间组成，其中内核空间就是整个Linu×系统的核心，Linu×启动后首先会加bootfs文件系统，加载完成后会自动卸载掉，之后会加载用户空间的文件系统，这一层是我们自己可以进行操作的部分：

- bootfs包含了BootLoader和Linux内核，用户是不能对这层作任何修改的，在内核启动之后，bootfs会自动卸载。
- rootfs则包含了系统上的常见的目录结构，包括/dev、/proc、/bin等等以及一些基本的文件和命令，也就是我们进入系统之后能够操作的整个文件系统，包括我们在Ubuntu下使用的apt和CentOS下使用的yum,都是用户空间上的。

base镜像底层会直接使用宿主主机的内核，也就是说你的Ubuntu内核版本是多少，那么base镜像中的内核版本就是多少，而rootfs则可以在不同的容器中运行多种不同的版本。所以，base镜像实际上只有CentOS的rootfs
 
对于直接启动相应的镜像，由于没有东西执行会立即退出，可以新建一个终端  
docker run -it ubuntu  
要让终端保持运行，按住ctrl+p+q，也可以附加回到指定容器  
docker attach \<容器ID\>  
可以启动时进入到终端  
docker start -i \<容器ID\>  
已经运行的容器，要新建一个终端  
docker exec -it \<容器ID\> bash  
自动后台运行  
docker run -d xxx
 
基于base镜像，可以在这基础上安装各种各样的软件

![Exported image](Exported%20image%2020260731091436-0.png)

每安装一个软件，就在base镜像上一层层叠加上去，采用的是一种分层的结构，这样多个容器都可以将这些不同的层次自由拼装，比如现在好几个容器都需要使用CentOS的base镜像，而上面运行的软件不同，此时分层结构就很爽了，我们只需要在本地保存一份base镜像，就可以给多个不同的容器拼装使用  
最上层是一个可写容器层：  
所有的镜像会叠起来组成一个统一的文件系统，如果不同层中存在相同位置的文件，那么上层的会覆盖掉下层的文件，最终我们看到的是一个叠加之后的文件系统。当我们需要修改容器中的文件时，实际上并不会对镜像进行直接修改，而是在最顶上的容器层（最上面一般称为容器层，下面都是镜像层）进行修改，不会影响到下面的镜像，否则镜像就很难实现多个容器共享了。所以各个操作如下：

- 文件读取：要读取一个文件，docker会最上层往下依次寻找，找到后则打开文件。
- 文件创建和修改：创建新文件会直接添加到容器层中，修改文件会从上往下依次寻找各个镜像中的文件，如果找到，则将其复制到容器层，再进行修改。
- 删除文件：删除文件也会从上往下依次寻找各个镜像中的文件，一旦找到，并不会直接删除镜像中的文件，而是在容器层标记这个删除操作。

**构建镜像**  
将镜像保存为文件  
docker save -o xxx.tar 镜像名:版本  
基于dockerfile的形式创建镜像（推荐）：  
我们可以新建一个dockerfile的文件  
touch dockerfile  
然后编辑，里面需要多条指令来告诉docker镜像相关信息，下面是选择当前镜像的基础镜像  
FROM \<基础镜像\>  
需要用到RUN命令，在容器中运行命令，如  
RUN apt update  
RUN apt install -y openjdk-8-jdk  
于是就编写完成了，只需要完成一次构建即可  
docker build -t \<镜像名称\> \<构建目录(dockerfile在哪就是哪)\>  
commit创建（具有历史）  
docker commit -m "描述" -a "作者" 容器id 镜像名:版本  
扁平化镜像  
docker export \<容器ID或名称\> \> container-flat.tar  
cat container-flat.tar | docker import \  
-c 'CMD ["/bin/bash"]' \  
-c 'ENV APP_ENV=production' \  
-m "描述信息" \  
- 镜像名:latest
 
**发布到远程仓库**  
[https://hub.docker.com/repositories](https://hub.docker.com/repositories)  
需要手动在网站上建仓库，结果一般是 个人名字/镜像名  
需要修改镜像的tag，可以  
docker tag 原名称:原标签(刚生成一般是latest) 个人名字/镜像名:版本  
需要在终端登录docker  
docker login -u username  
然后就可以上传  
docker push 个人名字/镜像名称:版本  
注意公共镜像是可以下载的，我们可以把本地镜像全部删掉，去下载上传的镜像，我们可以先搜索  
docker search 个人名字/镜像名  
然后就可以下载  
docker pull 个人名字/镜像名
