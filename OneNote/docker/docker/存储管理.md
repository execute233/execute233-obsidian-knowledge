# 存储管理

## 容器持久化存储

容器在创建之后，我们在容器中创建和修改的文件，实际上是被容器的分层机制保存在最顶层的容器层进行操作的，为了保护下面每一层的镜像不被修改，所以才有了这样的 CopyOnWrite 特性。但是这样也会导致容器在销毁时数据的丢失，当我们销毁容器重新创建一个新的容器时，所有的数据全部丢失，直接回到梦开始的地方。

在某些情况下，我们可能希望对容器内的某些文件进行持久化存储，而不是一次性的，这里就要用到数据卷（DataVolume）了。

可以让容器将文件保存在宿主主机上，下次创建容器时依然可以从宿主主机上读取对应的文件，通过挂载方式即可：

```bash
docker run -it -v 指定宿主机目录:挂载到容器中的目录 xxx
```

如果不指定宿主主机目录，那么 docker 会自动创建目录，并将容器中对应路径下的内容拷贝到自动创建的目录中，最后挂载在容器中，便是数据卷。

可以查看容器的信息，通过：

```bash
docker inspect 容器名/容器ID
```

也可以在宿主机和容器间传输数据，使用：

```bash
docker cp 宿主机文件 容器名:容器内的路径
docker cp 容器名:容器内的路径 宿主机文件
```

## 容器数据共享

需要 docker 使用数据卷，创建数据卷：

```bash
docker volume create 数据卷名
```

查看已经创建的数据卷：

```bash
docker volume ls
```

查看指定数据卷的详细信息：

```bash
docker volume inspect 数据卷名
```

在启动容器时挂载数据卷：

```bash
docker run -it -v 数据卷名:容器中的挂载路径 镜像名
```

可以将主机目录映射在容器里：

```bash
docker run -it -v 主机目录:容器中的目录 镜像名
```

也可以将另一个容器挂载的目录，直接在容器启动时指定使用此容器挂载的目录：

```bash
docker run -it --volumes-from 另一个容器名 镜像名
```

可以在 dockerfile 里面使用指定的指令：

```dockerfile
ADD 当前工作目录的文件路径 镜像的指定路径    # 将文件放在容器里,注意可以自动解压 tar.gz
VOLUME 容器中的路径                          # 类似于 -v 参数,将指定路径声明为 docker 挂载点
```
