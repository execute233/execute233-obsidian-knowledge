# 1. 从最简单的 Pipeline 开始

例如：

```powershell
Get-Process |
    Sort-Object CPU -Descending |
    Select-Object -First 5
```

可以画成：

```text
Get-Process
      │
      │ Process
      ▼
Sort-Object
      │
      │ Process
      ▼
Select-Object
      │
      ▼
最终结果
```

第一课我们把这个模型简单理解为：

```text
对象 → 对象 → 对象
```

这个理解是正确的。

但实际上，还缺了一个关键问题：

> 后面的 Cmdlet 是怎么知道前面的对象应该交给自己的哪个参数的？

答案是：

```text
Parameter Binding
参数绑定
```

这个机制才是 PowerShell Pipeline 真正的核心。

---

# 2. Pipeline 并不是“任何命令都能接”

例如：

```powershell
Command-A | Command-B
```

并不意味着：

> PowerShell 随便把 A 的结果塞给 B。

官方文档明确说明：

> 接收端 Cmdlet 必须存在能够接受 Pipeline Input 的参数。

也就是说：

```text
Command-A
     │
     │ Object
     ▼
Command-B
     │
     └── 必须找到一个
         Accept pipeline input = True
         的参数
```

否则 Pipeline 就会失败。

---

# 3. 怎么知道一个参数能不能接 Pipeline？

使用我们第一课学过的：

```powershell
Get-Help
```

例如：

```powershell
Get-Help Start-Service -Full
```

或者：

```powershell
Get-Help Start-Service -Parameter *
```

你会看到类似：

```text
Accept pipeline input?
True (ByValue)

或者

True (ByPropertyName)
```

这两个词非常重要：

```text
ByValue
ByPropertyName
```

马上详细解释。

---

# 4. Pipeline 实际上是一条对象流

官方文档指出，当多个对象通过 Pipeline 传递给命令时，PowerShell 通常会**一个一个地发送对象**。

例如：

```powershell
1, 2, 3 |
    ForEach-Object {
        "处理 $_"
    }
```

逻辑上可以理解成：

```text
1 ──→ ForEach-Object

2 ──→ ForEach-Object

3 ──→ ForEach-Object
```

而不是：

```text
[1, 2, 3]
    ↓
整个数组一次性交过去
```

这是非常重要的区别。

---

# 5. Pipeline 自动枚举

例如：

```powershell
$array = @(1, 2, 3)

$array | Measure-Object
```

结果：

```text
Count : 3
```

为什么不是：

```text
Count : 1
```

因为 PowerShell 会枚举 Array：

```text
@(1, 2, 3)

    ↓ 自动枚举

1
2
3

    ↓ Pipeline

Measure-Object
```

官方文档说明，PowerShell Pipeline 会自动枚举实现 `IEnumerable` 的类型，然后将枚举出来的成员逐个传下去。`String` 和一些字典类对象存在特殊规则，例如字符串不会被拆成一个个字符。

# 6. 一个非常容易踩的坑

比较：

```powershell
Get-Process | Get-Member
```

和：

```powershell
Get-Member -InputObject (Get-Process)
```

它们不是一回事。

第一种：

```text
Get-Process
    ↓
Process
Process
Process
    ↓
Get-Member
```

看到的是：

```text
System.Diagnostics.Process
```

第二种：

```text
Get-Process
    ↓
Process[]
    ↓
作为一个 InputObject
    ↓
Get-Member
```

看到的可能是：

```text
System.Object[]
```

也就是：

> 一个数组对象。

Microsoft 官方专门拿这个例子解释 Pipeline 的逐对象处理。

# 7. `$_` 到底是什么？

我们一直在写：

```powershell
Get-Process |
    Where-Object {
        $_.CPU -gt 10
    }
```

这里：

```powershell
$_
```

是 PowerShell 的自动变量。

在 `Where-Object`、`ForEach-Object` 等处理 Pipeline 对象的 ScriptBlock 中，它通常代表：

> 当前正在处理的 Pipeline 对象。

`$PSItem` 是 `$_` 的同义名称。PowerShell 官方将 `$_` 列为自动变量。

所以：

```powershell
$_.ProcessName
```

相当于：

```text
当前对象.ProcessName
```

---

# 8. 用 Java Lambda 理解 `$_`

PowerShell：

```powershell
Get-Process |
    Where-Object {
        $_.WorkingSet64 -gt 500MB
    }
```

概念上很像：

```java
processes.stream()
    .filter(process ->
        process.getWorkingSet64() > 500 * MB
    );
```

于是：

```text
PowerShell $_
```

可以暂时类比 Java Lambda 中的：

```text
process
```

但要注意：

> 这是帮助理解的类比，不意味着 PowerShell Pipeline 和 Java Stream 在实现方式、延迟求值和执行模型上完全相同。

---

# 9. ScriptBlock

看到：

```powershell
{
    $_.WorkingSet64 -gt 500MB
}
```

这一对：

```text
{ }
```

包起来的东西叫：

```text
ScriptBlock
```

官方定义中，ScriptBlock 是可以作为一个单元使用的一组语句或表达式；它本身也是一个：

```text
System.Management.Automation.ScriptBlock
```

对象。

例如：

```powershell
$block = {
    Get-Date
}
```

查看类型：

```powershell
$block.GetType()
```

然后执行：

```powershell
& $block
```

---

# 10. ScriptBlock 可以接受参数

例如：

```powershell
$add = {
    param(
        $a,
        $b
    )

    $a + $b
}
```

执行：

```powershell
& $add 10 20
```

结果：

```text
30
```

ScriptBlock 可以返回输出，也可以定义参数。

以后写：

```powershell
Where-Object { ... }

ForEach-Object { ... }

Sort-Object { ... }
```

时，你实际上都在向 Cmdlet 传递：

```text
ScriptBlock Object
```

---

# 11. `Where-Object`：过滤

官方定义非常直接：

> 根据对象属性值，从传入的对象集合中选择符合条件的对象。

例如：

```powershell
Get-Process |
    Where-Object {
        $_.WorkingSet64 -gt 500MB
    }
```

逻辑：

```text
Process
   ↓
条件为 True？
   ├── Yes → 输出这个 Process
   └── No  → 丢弃
```

---

# 12. `Where-Object` 的两种主要写法

完整 ScriptBlock：

```powershell
Get-Service |
    Where-Object {
        $_.Status -eq "Running"
    }
```

简化语法：

```powershell
Get-Service |
    Where-Object Status -EQ Running
```

从 Windows PowerShell 3.0 开始，`Where-Object` 同时支持 ScriptBlock 和简化比较语法。官方文档确认这两种写法可以完成相同过滤。

简单条件推荐：

```powershell
Where-Object Status -EQ Running
```

复杂条件：

```powershell
Where-Object {
    $_.Status -eq "Running" -and
    $_.Name -like "Win*"
}
```

---

# 13. 为什么复杂条件要用 ScriptBlock？

例如：

```powershell
Get-Process |
    Where-Object {
        $_.WorkingSet64 -gt 500MB -and
        $_.ProcessName -like "java*"
    }
```

官方文档指出，`-and`、`-or` 等逻辑组合不能直接用于 `Where-Object` 的简化比较形式；这种情况应使用 ScriptBlock。

---

# 14. 常见过滤模式

等于：

```powershell
Where-Object Status -EQ Running
```

大于：

```powershell
Where-Object WorkingSet64 -GT 500MB
```

通配符：

```powershell
Where-Object ProcessName -Like "java*"
```

正则：

```powershell
Where-Object ProcessName -Match "^java"
```

集合：

```powershell
Where-Object Extension -In ".java", ".kt", ".xml"
```

复杂组合：

```powershell
Where-Object {
    $_.Extension -in ".java", ".kt" -and
    $_.Length -gt 10KB
}
```

`Where-Object` 的 PowerShell 7.6 官方语法包括 `-EQ`、`-GT`、`-Like`、`-Match`、`-In`、`-Contains` 等多个比较参数集。

---

# 15. `Select-Object`：对象投影

`Select-Object` 的官方定义是：

> 选择对象，或者选择对象的属性。

例如：

```powershell
Get-Process |
    Select-Object ProcessName, Id
```

可以理解为：

```text
Process
├── Id
├── ProcessName
├── CPU
├── Handles
├── WorkingSet64
├── StartTime
└── ...

           ↓ Select

新对象
├── ProcessName
└── Id
```

这一步在数据处理中通常叫：

```text
Projection
投影
```

---

# 16. `Select-Object` 和 `Format-Table` 不一样

这两个看起来很像：

```powershell
Get-Process |
    Select-Object Name, Id
```

和：

```powershell
Get-Process |
    Format-Table Name, Id
```

但目的不同。

`Select-Object`：

```text
改变/创建对象的属性表示
```

`Format-Table`：

```text
控制最终显示格式
```

所以在需要继续处理数据时：

```powershell
Get-Process |
    Select-Object Name, Id |
    ...
```

通常是合理的。

而 `Format-*` 一般应该放在输出链路最后，因为它的目标是格式化显示而不是继续进行业务数据处理。PowerShell 官方 Pipeline 文档也将 formatting cmdlet 归类为 Pipeline 的输出/格式化环节。

---

# 17. 选择前 N 个对象

例如：

```powershell
Get-Process |
    Select-Object -First 5
```

后五个：

```powershell
Get-Process |
    Select-Object -Last 5
```

跳过：

```powershell
Get-Process |
    Select-Object -Skip 10
```

`Select-Object` 还支持 `-Unique`、`-Index`、`-ExpandProperty` 等选择方式。

---

# 18. `-ExpandProperty`

例如：

```powershell
Get-Process |
    Select-Object -ExpandProperty ProcessName
```

得到的是：

```text
chrome
java
idea64
pwsh
...
```

而：

```powershell
Get-Process |
    Select-Object ProcessName
```

得到的是具有：

```text
ProcessName
```

属性的对象。

可以实验：

```powershell
Get-Process |
    Select-Object ProcessName |
    Get-Member
```

然后比较：

```powershell
Get-Process |
    Select-Object -ExpandProperty ProcessName |
    Get-Member
```

第二个会得到字符串类型。

官方文档说明，`ExpandProperty` 会展开指定属性的值，而不是仅创建包含该属性的投影对象。

---

# 19. Calculated Property：计算属性

这是 PowerShell 非常强大的功能。

比如：

```powershell
Get-Process |
    Select-Object ProcessName,
        @{
            Name = "MemoryMB"
            Expression = {
                [Math]::Round(
                    $_.WorkingSet64 / 1MB,
                    2
                )
            }
        }
```

我们凭空创建了：

```text
MemoryMB
```

属性。

官方称这种机制为：

```text
Calculated Property
```

计算属性允许 Cmdlet 根据输入对象属性动态生成新的属性；在计算表达式内部可以使用 `$_` 或 `$PSItem` 获取当前输入对象。

---

# 20. 计算属性的结构

常见写法：

```powershell
@{
    Name = "MemoryMB"
    Expression = {
        $_.WorkingSet64 / 1MB
    }
}
```

实际上就是一个：

```text
Hashtable
```

核心成员：

```text
Name
Expression
```

经常缩写：

```powershell
@{
    N = "MemoryMB"
    E = {
        $_.WorkingSet64 / 1MB
    }
}
```

PowerShell 官方 Calculated Properties 文档规定了不同 Cmdlet 支持的计算属性键；`Select-Object` 支持为输出创建新的计算属性。

---

# 21. 一个开发者很常用的例子

```powershell
Get-ChildItem -File |
    Select-Object Name,
        @{
            Name = "SizeMB"
            Expression = {
                [Math]::Round(
                    $_.Length / 1MB,
                    2
                )
            }
        }
```

例如：

```text
Name               SizeMB
----               ------
app.jar            83.24
application.log   124.53
README.md           0.02
```

这里的思想就是：

```text
原始对象
    ↓
读取 Length
    ↓
计算
    ↓
生成 SizeMB
```

# 22. `Sort-Object`

官方定义：

> 根据对象属性值，以升序或降序排序对象。

例如：

```powershell
Get-Process |
    Sort-Object WorkingSet64
```

默认升序。

降序：

```powershell
Get-Process |
    Sort-Object WorkingSet64 -Descending
```

---

# 23. 多属性排序

例如：

```powershell
Get-Process |
    Sort-Object ProcessName, Id
```

首先：

```text
ProcessName
```

排序。

如果相同，再：

```text
Id
```

排序。

官方文档确认 `Sort-Object` 可以按照一个或多个属性排序，多属性排序按照属性声明顺序依次比较。

---

# 24. 不同字段使用不同排序方向

例如：

```powershell
Get-ChildItem |
    Sort-Object -Property @(
        @{
            Expression = "LastWriteTime"
            Descending = $true
        },
        @{
            Expression = "Name"
            Ascending = $true
        }
    )
```

也就是说：

```text
LastWriteTime ↓

相同时：

Name ↑
```

`Sort-Object` 官方支持使用 Hashtable 为每个排序表达式分别指定 `Ascending` 或 `Descending`。

---

# 25. ScriptBlock 排序

不仅能：

```powershell
Sort-Object Length
```

还可以：

```powershell
Get-ChildItem -File |
    Sort-Object {
        $_.Length / 1MB
    }
```

`Sort-Object` 的 Property 可以使用计算表达式，这也是 Calculated Property 机制的一个应用场景。

# 26. `ForEach-Object`

官方定义：

> 对输入集合中的每一个对象执行操作。

例如：

```powershell
1..5 |
    ForEach-Object {
        $_ * 2
    }
```

得到：

```text
2
4
6
8
10
```

逻辑：

```text
1 → 1 * 2 → 2
2 → 2 * 2 → 4
3 → 3 * 2 → 6
...
```

---

# 27. `ForEach-Object` 与 Java `map`

例如：

```powershell
Get-Process |
    ForEach-Object {
        $_.ProcessName
    }
```

概念上接近：

```java
processes.stream()
    .map(Process::getProcessName)
```

当然，PowerShell 更自由。

例如：

```powershell
Get-Process |
    ForEach-Object {
        [PSCustomObject]@{
            Name = $_.ProcessName
            PID  = $_.Id
        }
    }
```

---

# 28. `ForEach-Object` 的简化语法

官方文档还支持：

```powershell
Get-Process |
    ForEach-Object ProcessName
```

等价思路：

```powershell
Get-Process |
    ForEach-Object {
        $_.ProcessName
    }
```

也能调用方法。

例如字符串：

```powershell
"hello", "powershell" |
    ForEach-Object ToUpper
```

`ForEach-Object` 从 Windows PowerShell 3.0 起支持成员访问形式，不一定必须写 ScriptBlock。

---

# 29. `ForEach-Object` VS `foreach`

这两个经常被混淆。

Cmdlet：

```powershell
Get-Process |
    ForEach-Object {
        $_.ProcessName
    }
```

语言结构：

```powershell
foreach ($process in Get-Process) {
    $process.ProcessName
}
```

官方将 `foreach` 定义为 PowerShell 的语言结构，而 `ForEach-Object` 是 Cmdlet。`foreach` 遍历集合，而 `ForEach-Object` 很自然地处于 Pipeline 中处理输入对象。

初学阶段可以暂时这样选：

```text
正在写 Pipeline
    ↓
ForEach-Object

正在写较复杂流程控制
    ↓
foreach
```

---

# 30. `ForEach-Object -Begin / -Process / -End`

完整版：

```powershell
Get-Process |
    ForEach-Object `
        -Begin {
            "开始"
        } `
        -Process {
            $_.ProcessName
        } `
        -End {
            "结束"
        }
```

逻辑：

```text
Begin
  ↓
只运行一次

Process
  ↓
每个输入对象运行一次

End
  ↓
最后运行一次
```

官方文档明确支持这三个 ScriptBlock 阶段。

这和以后写 Advanced Function 的：

```powershell
begin {}
process {}
end {}
```

关系非常密切。

# 31. `Group-Object`

官方定义：

> 根据指定属性中相同的值对对象分组。

例如：

```powershell
Get-Process |
    Group-Object ProcessName
```

结果类似：

```text
Count Name
----- ----
   20 chrome
    6 svchost
    3 java
    2 pwsh
```

逻辑类似 SQL：

```sql
GROUP BY ProcessName
```

---

# 32. 查看 Group 内部对象

```powershell
$groups =
    Get-Process |
    Group-Object ProcessName
```

查看：

```powershell
$groups | Get-Member
```

默认返回：

```text
GroupInfo
```

每一组都有：

```text
Name
Count
Group
```

例如：

```powershell
$groups[0].Group
```

就是：

> 该组里面真正的 Process 对象。

官方文档说明 `Group-Object` 默认返回 `GroupInfo`，每个分组保存组名、数量以及组内成员。

---

# 33. `-NoElement`

如果只需要统计：

```powershell
Get-Process |
    Group-Object ProcessName -NoElement |
    Sort-Object Count -Descending
```

就无需显示每组成员。

类似：

```text
Count Name
----- ----
   25 chrome
   12 svchost
    5 java
```

`-NoElement` 会省略分组中的成员，只保留分组统计信息。

---

# 34. `Group-Object -AsHashTable`

还有一种非常好玩的方式：

```powershell
$groups =
    Get-Process |
    Group-Object ProcessName -AsHashTable -AsString
```

然后可能：

```powershell
$groups["java"]
```

直接取得：

```text
所有 java Process
```

PowerShell 7 的 `Group-Object` 支持通过 `-AsHashTable` 返回 Hashtable。

---

# 35. `Measure-Object`

官方定义：

> 对对象的数值属性进行计算，也可以统计字符串对象中的字符、单词和行。

最简单：

```powershell
Get-Process |
    Measure-Object
```

得到：

```text
Count
```

# 36. 数值统计

例如：

```powershell
Get-Process |
    Measure-Object `
        -Property WorkingSet64 `
        -Minimum `
        -Maximum `
        -Average `
        -Sum
```

可以得到：

```text
Count
Average
Sum
Maximum
Minimum
```

`Measure-Object` 还支持：

```text
StandardDeviation
```

PowerShell 7.6 的官方语法也支持 `-AllStats`。

# 37. 计算所有进程使用的工作集内存

```powershell
$memory =
    Get-Process |
    Measure-Object `
        -Property WorkingSet64 `
        -Sum
```

然后：

```powershell
$memory.Sum / 1GB
```

为了可读性：

```powershell
[Math]::Round(
    $memory.Sum / 1GB,
    2
)
```

注意这里统计的是各进程 `WorkingSet64` 属性之和，不应该直接把它理解成操作系统任务管理器里的“全机实际物理内存使用量”，因为这是不同的系统指标。

# 38. `Tee-Object`

想象一条 Pipeline：

```text
A → B → C
```

有时候我们想：

```text
         → 保存副本
        /
A → B ─────────→ C
```

这就是：

```powershell
Tee-Object
```

官方定义：

> 将命令输出保存到文件或变量，同时继续把这些对象发送到 Pipeline 下游。

例如：

```powershell
Get-Process |
    Where-Object WorkingSet64 -GT 500MB |
    Tee-Object -Variable LargeProcesses |
    Sort-Object WorkingSet64 -Descending
```

Pipeline 继续执行，同时：

```powershell
$LargeProcesses
```

也保存了过滤后的对象。

---

# 39. `Tee-Object` 调试 Pipeline 非常方便

例如：

```powershell
Get-Process |
    Where-Object WorkingSet64 -GT 100MB |
    Tee-Object -Variable AfterFilter |
    Sort-Object WorkingSet64 -Descending |
    Select-Object -First 5
```

然后：

```powershell
$AfterFilter
```

你就能检查：

> 过滤阶段到底产生了什么。

这在长 Pipeline 调试时很好用。

---

# 40. `Compare-Object`

官方定义：

> 比较两组对象。

例如：

```powershell
$a = @(
    "Java"
    "Python"
    "PowerShell"
)

$b = @(
    "Java"
    "Go"
    "PowerShell"
)

Compare-Object $a $b
```

可能：

```text
InputObject SideIndicator
----------- -------------
Go          =>
Python      <=
```

---

# 41. `SideIndicator`

官方规则：

```text
<=
```

代表：

```text
只存在于 ReferenceObject
```

```text
=>
```

代表：

```text
只存在于 DifferenceObject
```

如果：

```powershell
-IncludeEqual
```

则：

```text
==
```

表示：

```text
两边都有
```

这是 `Compare-Object` 官方定义的结果表示方式。

# 42. 实战：比较部署前后的文件

例如：

```powershell
$before =

# 执行部署……

$after =
    Get-ChildItem .\app -File |
    Select-Object Name, Length

Compare-Object `
```

```text

```

# 43. 现在进入 Pipeline 真正核心：Parameter Binding

假设：

```powershell
Get-Process notepad |
    Stop-Process
```

奇怪的地方来了：

我们没有写：

```powershell
Stop-Process -Id ...
```

为什么 `Stop-Process` 知道要停止哪个进程？

因为：

```text
Get-Process
    ↓
System.Diagnostics.Process
    ↓
Parameter Binder
    ↓
找到 Stop-Process 某个
可以接受 Process 的参数
    ↓
完成绑定
```

这就是：

```text
Pipeline Parameter Binding
```

官方文档将 Parameter Binding 定义为 PowerShell 确定 Parameter Set 并把命令行或 Pipeline 中的值绑定给参数的过程。

---

# 44. ByValue

第一种方式：

```text
ValueFromPipeline
```

也常在帮助里看到：

```text
ByValue
```

核心思想：

> Pipeline 中对象本身的类型能够匹配目标参数需要的类型。

例如概念上：

```text
Process Object
      │
      ▼
-InputObject <Process[]>
```

类型匹配，于是绑定成功。

官方说明 `ValueFromPipeline` 根据输入值的类型进行参数绑定。

---

# 45. ByPropertyName

第二种：

```text
ValueFromPipelineByPropertyName
```

也就是：

```text
ByPropertyName
```

例如输入对象：

```text
Object
├── Name
└── Id
```

目标 Cmdlet：

```text
-Name
```

如果 `-Name` 支持：

```text
ValueFromPipelineByPropertyName
```

PowerShell 就可以尝试：

```text
Object.Name
       ↓
     -Name
```

绑定。

官方规定，ByPropertyName 要求输入对象具有与参数名或参数别名匹配的属性，并且类型必须匹配或能够转换。

# 46. Pipeline Binding 的顺序

这是非常值得记住的机制。

PowerShell 官方记录的 Pipeline Binding 顺序可以概括为：

```text
① ByValue
   精确类型匹配
        ↓
② ByPropertyName
   精确类型匹配
        ↓
③ ByValue
   尝试类型转换
        ↓
④ ByPropertyName
   尝试类型转换
```

也就是说：

```text
Exact
优先于
Type Conversion
```

并且首先尝试：

```text
ByValue
```

再尝试：

```text
ByPropertyName
```

这是官方 `about_Parameter_Binding` 明确描述的顺序。

# 49. Pipeline 与 Java Stream 对照

可以暂时建立下面这个脑内映射：

| PowerShell             | Java Stream / Collection 思想 |
| ---------------------- | --------------------------- |
| `\|`                   | 流式处理链                       |
| `Where-Object`         | `filter()`                  |
| `ForEach-Object`       | `map()` / `forEach()`       |
| `Select-Object`        | projection / `map()`        |
| `Sort-Object`          | `sorted()`                  |
| `Group-Object`         | `groupingBy()`              |
| `Measure-Object`       | aggregation                 |
| `Select-Object -First` | `limit()`                   |
| `$_`                   | Lambda 当前元素                 |
| ScriptBlock            | Lambda / callback 思想        |

比如：

```powershell
Get-Process |
    Where-Object WorkingSet64 -GT 100MB |
    Sort-Object WorkingSet64 -Descending |
    Select-Object -First 5 ProcessName, WorkingSet64
```

思维上接近：

```java
processes.stream()
    .filter(p -> p.getWorkingSet64() > MB * 100)
    .sorted(
        comparing(Process::getWorkingSet64)
            .reversed()
    )
    .limit(5)
    .map(...)
    .toList();
```

但这个映射只用于理解数据处理思路，不要把二者运行时机制视作完全相同。

# 50. 一个需要纠正的概念：`CPU`

前面课程里我们写过：

```powershell
Get-Process |
    Sort-Object CPU -Descending
```

这里更准确的说法应该是：

> 找出累计 CPU 时间最高的进程。

而不是：

> 当前 CPU 使用率最高的进程。

`Get-Process` 默认列名明确显示为：

```text
CPU(s)
```

PowerShell 官方示例同样这样显示。其底层 `System.Diagnostics.Process.TotalProcessorTime` 表示进程累计花费的处理器时间。

所以：

```powershell
$process.CPU
```

不能直接理解成：

```text
87%
```

这种实时 CPU Percent。

这是一个很常见的 PowerShell 进程分析坑。

# 62. 官方文档给我们的完整 Pipeline 模型

综合 Microsoft 官方文档，可以把 PowerShell Pipeline 理解成：

```text
Command A
    │
    │ 输出 Object
    ▼
自动枚举 Collection
    │
    │ 一个一个对象
    ▼
Parameter Binder
    │
    ├── ByValue
    │
    └── ByPropertyName
    │
    ▼
Command B
    │
    │ 输出 Object
    ▼
Command C
```

而：

```text
Where
Select
Sort
ForEach
Group
Measure
```

只是在这个对象流上执行不同的数据操作。

---

# 63. 一句话总结

> **PowerShell Pipeline 的本质不是 `|`，而是对象在命令之间流动，并通过 Parameter Binding 自动绑定到下游命令能够接受 Pipeline Input 的参数。**

如果这一句话真正理解了，那么：

```powershell
Get-Process |
    Where-Object WorkingSet64 -GT 100MB |
    Sort-Object WorkingSet64 -Descending |
    Select-Object -First 10 ProcessName, Id
```

就不应该再被看作：

```text
一串 PowerShell 魔法咒语
```

而应该被读成：

```text
获取 Process
    ↓
过滤 Process
    ↓
排序 Process
    ↓
选择前 10 个
    ↓
投影属性
```

这就是对象管道思维。
