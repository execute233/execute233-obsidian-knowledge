# 1. 从最简单的 Pipeline 开始

```powershell
Get-Process |
    Sort-Object CPU -Descending |
    Select-Object -First 5
```

可以画成：

```text
Get-Process
      │ Process
      ▼
Sort-Object
      │ Process
      ▼
Select-Object
      │
      ▼
最终结果
```

但关键问题是：后面的 Cmdlet 是怎么知道前面的对象应该交给自己的哪个参数？

答案是 `Parameter Binding`。

---

# 2. Pipeline 并不是"什么命令都能接"

```text
Command-A
     │ Object
     ▼
Command-B
     │
     └── 必须找到一个 Accept pipeline input = True 的参数
```

否则 Pipeline 就会失败。

---

# 3. 如何查看一个参数能否接 Pipeline

```powershell
Get-Help Start-Service -Full
```

或：

```powershell
Get-Help Start-Service -Parameter *
```

在帮助中查看：

```text
Accept pipeline input?
True (ByValue)
True (ByPropertyName)
```

---

# 4. Pipeline 实际上是一条对象流

```powershell
1, 2, 3 |
    ForEach-Object {
        "处理 $_"
    }
```

逻辑上可理解为：

```text
1 ──→ ForEach-Object
2 ──→ ForEach-Object
3 ──→ ForEach-Object
```

而不是把整个数组一次性交过去。官方文档明确指出 PowerShell Pipeline 会逐对象发送，PowerShell 会自动枚举 `IEnumerable` 集合后逐个传入。

---

# 5. Pipeline 自动枚举的坑

```powershell
Get-Process | Get-Member
```

看到的是 `System.Diagnostics.Process`。

```powershell
Get-Member -InputObject (Get-Process)
```

看到的可能是 `System.Object[]`，因为整个数组被作为单个 `InputObject` 处理。

---

# 6. $_ 是什么

`$_` 是 PowerShell 的自动变量，在 `Where-Object`、`ForEach-Object` 等处理 Pipeline 对象的 ScriptBlock 中，通常代表当前正在处理的 Pipeline 对象。`$PSItem` 是 `$_` 的同义名称。

```powershell
Get-Process |
    Where-Object {
        $_.CPU -gt 10
    }
```

Java Lambda 类比：

```java
processes.stream()
    .filter(process ->
        process.getCpu() > 10
    );
```

> [!warning]
> 这是帮助理解的类比，不意味着 PowerShell Pipeline 与 Java Stream 在实现机制、延迟求值、执行模型上完全相同。

---

# 7. ScriptBlock

```powershell
{
    $_.WorkingSet64 -gt 500MB
}
```

`{ }` 包起来的东西叫 `ScriptBlock`，本身也是 `System.Management.Automation.ScriptBlock` 对象。

```powershell
$block = {
    Get-Date
}

$block.GetType()

& $block
```

`&` 调用运算符可执行 ScriptBlock。

---

# 8. ScriptBlock 可以接受参数

```powershell
$add = {
    param(
        $a,
        $b
    )

    $a + $b
}

& $add 10 20
```

结果：

```text
30
```

# 9. Where-Object：过滤

官方定义：根据对象属性值从集合中选择符合条件的对象。

```powershell
Get-Process |
    Where-Object {
        $_.WorkingSet64 -gt 500MB
    }
```

逻辑：

```text
Process
   ↓
条件 True？
   ├── Yes → 输出
   └── No  → 丢弃
```

---

# 10. Where-Object 两种写法

ScriptBlock 形式：

```powershell
Get-Service |
    Where-Object {
        $_.Status -eq "Running"
    }
```

简化语法：

```powershell
Get-Service |
    Where-Object Status -EQ Running
```

复杂条件必须使用 ScriptBlock：

```powershell
Get-Process |
    Where-Object {
        $_.WorkingSet64 -gt 500MB -and
        $_.ProcessName -like "java*"
    }
```

`Where-Object` 从 Windows PowerShell 3.0 起同时支持 ScriptBlock 和简化比较语法。

---

# 11. 常见过滤模式

```powershell
Where-Object Status -EQ Running
Where-Object WorkingSet64 -GT 500MB
Where-Object ProcessName -Like "java*"
Where-Object ProcessName -Match "^java"
Where-Object Extension -In ".java", ".kt", ".xml"
```

# 12. Select-Object：对象投影

`Select-Object` 选择对象或对象的属性。

```powershell
Get-Process |
    Select-Object ProcessName, Id
```

这一步在数据处理中通常叫 `Projection`。

---

# 13. Select-Object 与 Format-Table

两者目的不同：

```text
Select-Object   改变/创建对象的属性表示
Format-Table    控制最终显示格式
```

需要继续处理数据时使用 `Select-Object`，`Format-*` 应放在输出链路最后。

---

# 14. First / Last / Skip

```powershell
Get-Process | Select-Object -First 5
Get-Process | Select-Object -Last 5
Get-Process | Select-Object -Skip 10
```

Get-Process |

```text

```

而不是包含 `ProcessName` 属性的对象。

# 16. Calculated Property：计算属性

```powershell
Get-Process |
    Select-Object ProcessName,
        @{
            Name = "MemoryMB"
            Expression = {
                [Math]::Round(
                    $_.WorkingSet64 / 1MB,
                    2
                )
            }
        }
```

凭空创建 `MemoryMB` 属性。`@{}` 是 Hashtable：

```text
Name        新属性名
Expression  计算逻辑，可用 $_
```

常用缩写：`N`、`E`。

---

# 17. 一个很常用的例子

```powershell
Get-ChildItem -File |
    Select-Object Name,
        @{
            Name = "SizeMB"
            Expression = {
                [Math]::Round(
                    $_.Length / 1MB,
                    2
                )
            }
        }
```

输出：

```text
Name             SizeMB
----             ------
app.jar          83.24
application.log  124.53
README.md         0.02
```

# 18. Sort-Object

```powershell
Get-Process | Sort-Object WorkingSet64
Get-Process | Sort-Object WorkingSet64 -Descending
```

多属性排序：

```powershell
Get-Process | Sort-Object ProcessName, Id
```

先按 `ProcessName`，相同再按 `Id`。

不同字段不同方向：

```powershell
Get-ChildItem |
    Sort-Object -Property @(
        @{
            Expression = "LastWriteTime"
            Descending = $true
        },
        @{
            Expression = "Name"
            Ascending = $true
        }
    )
```

# 19. ScriptBlock 排序

```powershell
Get-ChildItem -File |
    Sort-Object {
        $_.Length / 1MB
    }
```

# 20. ForEach-Object

```powershell
1..5 |
    ForEach-Object {
        $_ * 2
    }
```

得到：

```text
2
4
6
8
10
```

Java `map` 对照：

```powershell
Get-Process |
    ForEach-Object {
        [PSCustomObject]@{
            Name = $_.ProcessName
            PID  = $_.Id
        }
    }
```

---

# 21. ForEach-Object 简化语法

```powershell
Get-Process | ForEach-Object ProcessName

"hello", "powershell" | ForEach-Object ToUpper
```

`ForEach-Object` 从 Windows PowerShell 3.0 起支持成员访问形式。

---

# 22. ForEach-Object VS foreach

```powershell
Get-Process |
    ForEach-Object {
        $_.ProcessName
    }
```

是 Cmdlet。

```powershell
foreach ($process in Get-Process) {
    $process.ProcessName
}
```

是语言结构。`foreach` 适合较复杂流程控制，`ForEach-Object` 适合 Pipeline 场景。

---

# 23. ForEach-Object -Begin / -Process / -End

```powershell
Get-Process |
    ForEach-Object `
        -Begin {
            "开始"
        } `
        -Process {
            $_.ProcessName
        } `
        -End {
            "结束"
        }
```

逻辑：

```text
Begin    只运行一次
Process  每个输入对象运行一次
End      最后运行一次
```

后续写 Advanced Function 时 `begin{}` / `process{}` / `end{}` 与此对应。

# 24. Group-Object

```powershell
Get-Process |
    Group-Object ProcessName
```

结果类似 SQL `GROUP BY ProcessName`：

```text
Count Name
----- ----
   20 chrome
    6 svchost
    3 java
```

`-NoElement` 只保留统计信息：

```powershell
Get-Process |
    Group-Object ProcessName -NoElement |
    Sort-Object Count -Descending
```

`-AsHashTable` 返回 Hashtable：

```powershell
$groups =
    Get-Process |
    Group-Object ProcessName -AsHashTable -AsString

$groups["java"]
```

# 25. Measure-Object

```powershell
Get-Process | Measure-Object
```

得到 `Count`。

数值统计：

```powershell
Get-Process |
    Measure-Object `
        -Property WorkingSet64 `
        -Minimum `
        -Maximum `
        -Average `
        -Sum
```

统计所有进程工作集总内存：

```powershell
$memory =
    Get-Process |
    Measure-Object `
        -Property WorkingSet64 `
        -Sum

[Math]::Round(
    $memory.Sum / 1GB,
    2
)
```

> [!warning]
> `WorkingSet64` 之和并不等于任务管理器中的"全机物理内存使用量"，两者是不同指标。

---

# 26. Tee-Object

将命令输出保存到文件或变量，同时继续向下游传递：

```powershell
Get-Process |
    Where-Object WorkingSet64 -GT 500MB |
    Tee-Object -Variable LargeProcesses |
    Sort-Object WorkingSet64 -Descending
```

Pipeline 继续执行，`$LargeProcesses` 也保存了过滤后的对象。调试长 Pipeline 时非常方便。

---

# 27. Compare-Object

```powershell
$a = @("Java", "Python", "PowerShell")
$b = @("Java", "Go", "PowerShell")

Compare-Object $a $b
```

可能输出：

```text
InputObject SideIndicator
----------- -------------
Go          =>
Python      <=
```

SideIndicator：

```text
<=  只存在于 ReferenceObject
=>  只存在于 DifferenceObject
==  两边都有（需 -IncludeEqual）
```

按属性比较：

```powershell
Compare-Object `
    -ReferenceObject $before `
    -DifferenceObject $after `
    -Property Name, Length
```

# 28. Parameter Binding

```powershell
Get-Process notepad |
    Stop-Process
```

`Stop-Process` 没有显式 `-Id`，但 Pipeline 中的 Process 对象被绑定到了能接受 Pipeline Input 的参数。这就是 Parameter Binding。

---

# 29. ByValue

`ValueFromPipeline` 也常写作 `ByValue`。Pipeline 中对象本身的类型能够匹配目标参数需要的类型时，按 ByValue 绑定。

```text
Process Object
      │
      ▼
-InputObject <Process[]>
```

类型匹配，绑定成功。

---

# 30. ByPropertyName

`ValueFromPipelineByPropertyName`，按属性名匹配。例如输入对象有 `Name`、目标参数是 `-Name` 且支持 `ByPropertyName`，则把 `Object.Name` 绑定给 `-Name`。

ByPropertyName 要求输入对象具有与参数名或参数别名匹配的属性，且类型可匹配或可转换。

---

# 31. Binding 顺序

官方记录的顺序：

```text
① ByValue  精确类型匹配
② ByPropertyName  精确类型匹配
③ ByValue  尝试类型转换
④ ByPropertyName  尝试类型转换
```

即 `Exact` 优先于 `Type Conversion`，`ByValue` 优先于 `ByPropertyName`。

---

# 32. 排错思路

```text
A | B   报错
  ↓
A | Get-Member   看 A 输出什么类型
  ↓
Get-Help B -Full   看 B 哪些参数接 Pipeline
  ↓
看 ByValue / ByPropertyName
  ↓
看类型 / 属性是否匹配
```

仍然不知道就用 `Trace-Command`：

```powershell
Trace-Command `
    -Name ParameterBinding `
    -PSHost `
    -Expression {
        Get-Item *.txt |
            Remove-Item
    }
```

官方推荐用 `Trace-Command -Name ParameterBinding` 排查难以理解的参数绑定问题。

# 33. Pipeline 与 Java Stream 对照

| PowerShell             | Java Stream            |
| ---------------------- | --------------------- |
| `\|`                   | 流式处理链                |
| `Where-Object`         | `filter()`            |
| `ForEach-Object`       | `map()` / `forEach()` |
| `Select-Object`        | projection / `map()`  |
| `Sort-Object`          | `sorted()`            |
| `Group-Object`         | `groupingBy()`        |
| `Measure-Object`       | aggregation           |
| `Select-Object -First` | `limit()`             |
| `$_`                   | Lambda 当前元素          |
| ScriptBlock            | Lambda / callback 思想   |

这是数据处理思路的映射，不意味着二者运行时机制完全相同。

# 34. 关于 CPU 字段

```powershell
Get-Process | Sort-Object CPU -Descending
```

`Get-Process` 的 `CPU(s)` 列实际表示累计 CPU 时间，而不是瞬时使用率。底层 `Process.TotalProcessorTime` 表示进程累计花费的处理器时间。

这是 PowerShell 进程分析的常见坑。

# 35. 实战：进程与系统资源分析器

## 内存最高的 10 个进程

```powershell
Get-Process |
    Sort-Object WorkingSet64 -Descending |
    Select-Object -First 10 `
        ProcessName,
        Id,
        @{
            Name = "MemoryMB"
            Expression = {
                [Math]::Round(
                    $_.WorkingSet64 / 1MB,
                    2
                )
            }
        }
```

## 超过 500MB 工作集的进程

```powershell
Get-Process |
    Where-Object WorkingSet64 -GT 500MB |
    Select-Object `
        ProcessName,
        Id,
        @{
            Name = "MemoryMB"
            Expression = {
                [Math]::Round(
                    $_.WorkingSet64 / 1MB,
                    2
                )
            }
        }
```

## 按进程名称分组

```powershell
Get-Process |
    Group-Object ProcessName |
    Sort-Object Count -Descending |
    Select-Object -First 10 Count, Name
```

## 工作集统计

```powershell
$stats =
    Get-Process |
    Measure-Object `
        -Property WorkingSet64 `
        -Minimum -Maximum -Average -Sum

[PSCustomObject]@{
    ProcessCount     = $stats.Count
    AverageMemoryMB  = [Math]::Round($stats.Average / 1MB, 2)
    MaximumMemoryMB  = [Math]::Round($stats.Maximum / 1MB, 2)
    TotalWorkingSetGB = [Math]::Round($stats.Sum / 1GB, 2)
}
```

## 分析 Java 进程

```powershell
Get-Process |
    Where-Object ProcessName -Like "java*" |
    Sort-Object WorkingSet64 -Descending |
    Select-Object `
        ProcessName,
        Id,
        @{
            Name = "MemoryMB"
            Expression = {
                [Math]::Round(
                    $_.WorkingSet64 / 1MB,
                    2
                )
            }
        },
        @{
            Name = "CPUSeconds"
            Expression = {
                if ($null -ne $_.CPU) {
                    [Math]::Round(
                        $_.CPU,
                        2
                    )
                }
            }
        }
```

## Tee-Object 调试

```powershell
Get-Process |
    Where-Object WorkingSet64 -GT 100MB |
    Tee-Object -Variable LargeProcesses |
    Sort-Object WorkingSet64 -Descending |
    Select-Object -First 10 ProcessName, Id

$LargeProcesses.Count
```

# 36. Pipeline 思维图

```text
            Get-Process
                  │
                  ▼
           Process Object
                  │
                  ▼
           Where-Object
             filter()
                  │
                  ▼
           Process Object
                  │
                  ▼
            Sort-Object
             sorted()
                  │
                  ▼
           Process Object
                  │
                  ▼
           Select-Object
            projection
                  │
                  ▼
            New Object
```

`|` 背后还有：

```text
Pipeline Object
       ↓
Parameter Binder
       ↓
ByValue？
       ↓
ByPropertyName？
       ↓
目标参数
```

所以真正理解 PowerShell Pipeline 应该是：

```text
对象流 + 参数绑定 + 对象变换
```
