---

# 1. PowerShell 变量

PowerShell 变量使用：

```powershell
$
```

开头。

例如：

```powershell
$name = "Ema"
$age = 15
$enabled = $true
```

读取：

```powershell
$name
$age
$enabled
```

PowerShell 变量名默认：

```text
不区分大小写
```

所以：

```powershell
$name = "PowerShell"

$Name
$NAME
$name
```

实际上指向同一个变量。Microsoft 官方还说明，变量名可以包含空格和特殊字符，不过实际脚本中通常应避免这么做。

---

# 2. PowerShell 是动态类型吗？

看这个实验：

```powershell
$value = 100
$value.GetType()
```

得到：

```text
System.Int32
```

然后：

```powershell
$value = "Hello"
$value.GetType()
```

变成：

```text
System.String
```

再来：

```powershell
$value = Get-Date
$value.GetType()
```

变成：

```text
System.DateTime
```

所以：

```text
$value
```

并没有永远被声明成某种固定类型。

PowerShell 默认根据当前赋给变量的 .NET 对象决定其类型；同一个未受类型约束的变量可以在不同时间保存不同类型的值。

---

# 3. 和 Java 对比

Java：

```java
int age = 15;
```

意味着：

```text
age 永远是 int
```

不能：

```java
age = "hello";
```

但是 PowerShell：

```powershell
$age = 15

$age = "hello"
```

完全可以。

因此：

```text
Java
    ↓
变量声明通常带静态类型

PowerShell
    ↓
变量默认没有固定类型约束
```

# 4. 查看一个值的真实类型

最直接：

```powershell
$value.GetType()
```

例如：

```powershell
$a = 123
$a.GetType().FullName
```

得到：

```text
System.Int32
```

字符串：

```powershell
$a = "123"
$a.GetType().FullName
```

得到：

```text
System.String
```

# 5. 使用 `Get-Member`

上一课的方法仍然有效：

```powershell
$a | Get-Member
```

不过要注意：

```powershell
$array | Get-Member
```

会因为 Pipeline 自动枚举而观察数组里面的成员。

如果真正想观察数组对象：

```powershell
Get-Member -InputObject $array
```

这个区别在上一课讲过。

# 6. 常见 .NET 类型

PowerShell 建立在 .NET 类型系统上，因此常见值实际上都是 .NET 对象。

常见对应关系：

| PowerShell 写法 | .NET 类型                        |
| ------------- | ------------------------------ |
| `[byte]`      | `System.Byte`                  |
| `[int]`       | `System.Int32`                 |
| `[long]`      | `System.Int64`                 |
| `[float]`     | `System.Single`                |
| `[double]`    | `System.Double`                |
| `[decimal]`   | `System.Decimal`               |
| `[string]`    | `System.String`                |
| `[bool]`      | `System.Boolean`               |
| `[datetime]`  | `System.DateTime`              |
| `[timespan]`  | `System.TimeSpan`              |
| `[array]`     | `System.Array`                 |
| `[hashtable]` | `System.Collections.Hashtable` |

这些：

```text
[int]
[string]
[datetime]
```

通常被称为：

```text
Type Accelerator
类型加速器
```

也就是某些常用 .NET 类型名称的简短写法。

---

# 7. 强制类型转换

比如：

```powershell
$value = "123"
```

它是：

```text
String
```

可以：

```powershell
[int]$value
```

得到：

```text
123
```

并且结果类型：

```powershell
([int]$value).GetType().Name
```

是：

```text
Int32
```

PowerShell 支持通过：

```powershell
[Type] expression
```

执行显式类型转换。

---

# 8. 强类型变量

还可以直接约束变量：

```powershell
[int]$port = 8080
```

现在：

```powershell
$port = "9000"
```

PowerShell 会尝试：

```text
"9000"
↓
转换为 Int32
↓
9000
```

因此：

```powershell
$port.GetType().Name
```

仍然是：

```text
Int32
```

PowerShell 官方称这种变量为：

```text
Type-constrained variable
类型约束变量
```

赋值时，PowerShell 会尝试把新值转换成要求的类型；无法转换时则产生错误。

---

# 9. 转换失败

例如：

```powershell
[int]$port = 8080

$port = "hello"
```

PowerShell 无法把：

```text
hello
```

转换成：

```text
Int32
```

于是报错。

所以：

```powershell
[int]$port
[string]$name
[datetime]$startTime
```

不仅是文档信息，还能提供一定程度的运行时约束。

---

# 10. 数字 Literal

PowerShell 整数 Literal 可以使用：

```powershell
123
```

十六进制：

```powershell
0xFF
```

二进制：

```powershell
0b11111111
```

PowerShell 还支持数字类型后缀和容量 multiplier。

例如：

```powershell
1KB
1MB
1GB
1TB
```

这里不是十进制 SI 单位，而是二进制乘数：

```text
1KB = 1024
1MB = 1024²
1GB = 1024³
1TB = 1024⁴
```

所以：

```powershell
500MB
```

其实就是一个数字表达式。

这也是为什么：

```powershell
$_.WorkingSet64 -gt 500MB
```

可以直接工作。

# 11. 算术运算符

基本运算：

```powershell
10 + 5
10 - 5
10 * 5
10 / 5
10 % 3
```

分别：

```text
+
-
*
/
%
```

PowerShell 的 `+` 和 `*` 不只作用于数字：`+` 还可以连接字符串、数组和 Hashtable；运算行为会受到最左侧操作数类型影响。

---

# 12. 字符串的 `+`

```powershell
"Power" + "Shell"
```

得到：

```text
PowerShell
```

---

# 13. 数组的 `+`

```powershell
$array1 = @(1, 2)
$array2 = @(3, 4)

$array1 + $array2
```

得到：

```text
1
2
3
4
```

也就是说：

```text
Array + Array
    ↓
连接集合
```

---

# 14. 一个极其重要的规则

PowerShell 运算过程中，经常由：

```text
左操作数
```

决定应使用什么类型进行计算或比较。

Microsoft 的类型转换文档专门强调：

> PowerShell 操作符通常根据左操作数的类型决定运算所需类型，然后尝试转换右操作数。

例如：

```powershell
10 - "9"
```

得到：

```text
1
```

因为：

```text
左边 10
↓
Int32

右边 "9"
↓
尝试转换 Int32
↓
9
```

# 15. 比较运算符

PowerShell 不使用 Java 风格：

```text
==
!=
>
<
```

而主要使用：

```text
-eq
-ne
-gt
-ge
-lt
-le
```

对应：

| PowerShell | 含义               |
| ---------- | ---------------- |
| `-eq`      | equal            |
| `-ne`      | not equal        |
| `-gt`      | greater than     |
| `-ge`      | greater or equal |
| `-lt`      | less than        |
| `-le`      | less or equal    |

---

# 16. 普通比较

```powershell
10 -eq 10
```
：
```text
True
```


```powershell
10 -gt 5
```
：
```text
True
```


```powershell
10 -le 5
```
：
```text
False
```

---

# 17. PowerShell 自动转换类型

来看：

```powershell
1 -eq "1.0"
```

结果是：

```text
True
```

为什么？

因为左边是：

```text
Int32
```

PowerShell 尝试把右边：

```text
"1.0"
```

转换成整数后比较。

PowerShell 官方文档用这个例子说明了比较运算中的类型转换行为。

---

# 18. 交换左右顺序可能改变结果

来看：

```powershell
1 -eq "1.0"
```

和：

```powershell
"1.0" -eq 1
```

PowerShell 比较时会依据左操作数类型去转换右操作数，因此左右顺序在混合类型比较中可能改变语义。

这和 Java 非常不同。

所以正式脚本中不要依赖模糊的隐式转换。

推荐：

```powershell
[int]$port = 8080
```

而不是让：

```text
String
Int32
Double
```

在各种表达式里自由互转。

---

# 19. 字符串比较默认忽略大小写

PowerShell：

```powershell
"PowerShell" -eq "powershell"
```

结果：

```text
True
```

默认字符串比较不区分大小写。比较运算符还提供显式的大小写敏感和不敏感版本，例如 `-ceq` 和 `-ieq`。

---

# 20. 强制大小写敏感

使用：

```powershell
-ceq
```

其中：

```text
c
=
Case-sensitive
```

例如：

```powershell
"PowerShell" -ceq "powershell"
```

结果：

```text
False
```

---

显式大小写不敏感：

```powershell
-ieq
```

其中：

```text
i
=
case-Insensitive
```

例如：

```powershell
"PowerShell" -ieq "powershell"
```

结果：

```text
True
```

类似变体还有：

```text
-clike
-ilike

-cmatch
-imatch
```

---

# 21. 第一个 PowerShell 大坑：集合比较

来看：

```powershell
$array = 1, 2, 3, 4, 5

$array -eq 3
```

Java 开发者可能猜：

```text
False
```

因为：

```text
Array != 3
```

但 PowerShell 的结果是：

```text
3
```

为什么？

PowerShell 的比较运算符在左操作数是集合时，会对集合成员进行比较，并返回匹配的元素，而不是简单返回一个 Boolean。

---

# 22. 再看一个

```powershell
1, 2, 3, 2, 4 -eq 2
```

结果：

```text
2
2
```

也就是说：

```text
Collection -eq value
```

很像：

```text
filter
```

而不仅仅是：

```text
boolean compare
```

官方文档明确把比较运算符描述为既可以比较两个标量，也可以用一个输入值过滤集合成员。

---

# 23. Java 类比

PowerShell：

```powershell
$array -eq 2
```

思维上更像：

```java
array.stream()
    .filter(x -> x == 2)
    .toList();
```

而不是：

```java
array.equals(2);
```

---

# 24. `-ne` 也一样

```powershell
1, 2, 3, 2, 4 -ne 2
```

返回：

```text
1
3
4
```

相当于：

```text
过滤掉 2
```

---

# 25. 如果真的只是想知道“集合是否包含”

不要写：

```powershell
$array -eq 2
```

更清晰的是：

```powershell
$array -contains 2
```

结果：

```text
True
```

`-contains` 和 `-in` 属于 containment operators，它们即使面对集合也返回 Boolean，并在发现匹配后停止继续查找。

---

# 26. `-contains`

语义：

```text
集合
-contains
元素
```

例如：

```powershell
$extensions = ".java", ".kt", ".ps1"

$extensions -contains ".java"
```

：

```text
True
```

---

# 27. `-in`

语义刚好反过来：

```text
元素
-in
集合
```

例如：

```powershell
".java" -in $extensions
```

：

```text
True
```

因此：

```powershell
$extensions -contains ".java"
```

和：

```powershell
".java" -in $extensions
```

表达的是同一个关系，只是阅读方向不同。

---

# 28. Pipeline 中为什么经常用 `-in`

例如：

```powershell
Get-ChildItem -File |
    Where-Object {
        $_.Extension -in ".java", ".kt", ".ps1"
    }
```

读起来非常自然：

```text
当前文件.Extension
    ↓
是否在
    ↓
允许的 Extensions
```

---

# 29. `-like`

用于：

```text
Wildcard
通配符匹配
```

例如：

```powershell
"PowerShell" -like "Power*"
```

：

```text
True
```

常用通配符：

```text
*
?
```

例如：

```powershell
"application.yml" -like "*.yml"
```

---

# 30. `-match`

用于：

```text
Regular Expression
正则表达式
```

例如：

```powershell
"java-service-01" -match "^java-"
```

：

```text
True
```

又例如：

```powershell
"server-8080" -match "\d+"
```

：

```text
True
```

`-match` 使用正则表达式模式，而 `-like` 使用 wildcard 模式。

---

# 31. `-like` VS `-match`

简单文件名：

```powershell
$name -like "*.java"
```

比较自然。

复杂规则：

```powershell
$name -match "^application-(dev|prod)\.ya?ml$"
```

则使用正则更适合。

---

# 32. `-is`

PowerShell 可以测试一个对象是否属于指定 .NET 类型。

例如：

```powershell
$value = Get-Date

$value -is [datetime]
```

：

```text
True
```

```powershell
$value -is [string]
```

：

```text
False
```

`-is` 与 `-isnot` 始终返回 Boolean。它们判断输入对象是不是指定 .NET 类型或其派生类型的实例。

---

# 33. Array 的 `-is` 又有坑

例如：

```powershell
$a = Get-Date
$b = Get-Date

$a -is [datetime]
```

：

```text
True
```

但：

```powershell
@($a, $b) -is [datetime]
```

：

```text
False
```

因为这里测试的是：

```text
整个 Array
```

的类型，而不是每个 Array Element。

于是：

```powershell
@($a, $b) -is [array]
```

返回：

```text
True
```

官方 `about_Type_Operators` 特别强调：类型运算符作用于整个输入对象，不会自动枚举集合成员。

---

# 34. `-as`

`-as` 尝试进行类型转换：

```powershell
"2026-08-11" -as [datetime]
```

转换成功：

```text
DateTime Object
```

如果不能转换：

```powershell
"hello" -as [datetime]
```

则：

```text
$null
```

而不是抛出转换错误。

这是 `-as` 与直接 cast 的重要区别。

---

# 35. Cast VS `-as`

Cast：

```powershell
[int]"123"
```

成功。

但是：

```powershell
[int]"hello"
```

报错。

---

`-as`：

```powershell
"123" -as [int]
```

成功。

```powershell
"hello" -as [int]
```

失败时返回：

```powershell
$null
```

---

# 36. Boolean

PowerShell 原生 Boolean：

```powershell
$true
$false
```

类型：

```powershell
$true.GetType().FullName
```

：

```text
System.Boolean
```

但是 PowerShell 的条件判断可以把很多其他类型隐式转换成 Boolean。

---

# 37. 哪些东西是 False？

官方规则中，常见的 False 包括：

```text
$false

$null

数字 0

空字符串 ""

空集合 @()
```

例如：

```powershell
if (0) {
    "yes"
}
else {
    "no"
}
```

结果：

```text
no
```

---

# 38. 非空字符串是 True

这是一个很容易踩的坑：

```powershell
[bool]"False"
```

结果居然是：

```text
True
```

因为：

```text
"False"
```

只是一个：

```text
非空 String
```

而不是：

```powershell
$false
```

官方文档明确给出了这个例子。

所以：

```powershell
[bool]"false"
```

不是解析字符串里的 Boolean 含义。

如果真要解析：

```powershell
[bool]::Parse("false")
```

才会得到：

```text
False
```

---

# 39. Collection 转 Boolean 更奇怪

官方规则：

```text
空集合
↓
False

单元素集合
↓
看这个元素自己的 Boolean 值

两个及以上元素
↓
True
```

所以：

```powershell
[bool]@()
```

：

```text
False
```

```powershell
[bool]@(0)
```

：

```text
False
```

但是：

```powershell
[bool]@(0, 0)
```

：

```text
True
```

PowerShell 在这里真的很有自己的想法 `(・_・;)`

# 40. 逻辑运算符

PowerShell 使用：

```text
-and
-or
-xor
-not
!
```

例如：

```powershell
$a = 10

($a -gt 5) -and ($a -lt 20)
```

：

```text
True
```

---

# 41. 短路求值

`-and`：

如果左边已经是：

```text
False
```

右边不会执行。

`-or`：

如果左边已经是：

```text
True
```

右边不会执行。

这是官方规定的 short-circuit 行为。

因此：

```powershell
$null -ne $config -and
$config.Enabled
```

第一个条件失败后：

```powershell
$config.Enabled
```

不会继续求值。

---

# 42. 运算符优先级

PowerShell 有自己的运算符优先级，并不应该凭 Java/C#/JavaScript 的经验猜。

例如比较运算符：

```text
-gt
-eq
```

优先于：

```text
-and
-or
```

而且 PowerShell 的：

```text
-and
-or
-xor
```

彼此处于同一优先级组，按从左到右计算。

所以复杂表达式建议：

> 主动加括号。

例如：

```powershell
($a -gt 10) -and
(($b -eq "prod") -or ($b -eq "dev"))
```

而不是依赖记忆中的优先级。

---

# 43. `$null`

PowerShell 提供特殊自动变量：

```powershell
$null
```

它代表：

```text
没有值 / 空值
```

未赋值变量通常求值为 `$null`。

例如：

```powershell
$null -eq $undefinedVariable
```

：

```text
True
```

---

# 44. `$null` 应该放哪边？

推荐：

```powershell
$null -eq $value
```

不要：

```powershell
$value -eq $null
```

为什么？

因为刚才已经学过：

```text
比较运算行为
取决于左操作数是不是 Collection
```

如果：

```powershell
$value
```

碰巧是 Array：

```powershell
$value -eq $null
```

就会变成：

> 从集合中筛选 `$null` 元素。

而不是进行单纯的 Null Boolean 判断。

PSScriptAnalyzer 甚至有一条默认启用的规则专门警告这种写法，并建议始终把 `$null` 放在比较运算符左边。

---

# 45. 以后固定这么写

推荐：

```powershell
if ($null -eq $value) {

}
```

和：

```powershell
if ($null -ne $value) {

}
```

形成肌肉记忆。

# 46. 数组 Array

创建 Array：

```powershell
$numbers = 1, 2, 3, 4, 5
```

或者：

```powershell
$numbers = @(
    1
    2
    3
    4
    5
)
```

PowerShell Array 可以包含相同类型或不同类型的元素。

例如：

```powershell
$data = @(
```

# 64. Scope

PowerShell 不只有变量值，还有：

```text
Scope
作用域
```

PowerShell 的 Scope 可以嵌套。外层叫 Parent Scope，内层叫 Child Scope；变量、函数、Alias 等通常在创建它们的 Scope 和子 Scope 中可见。

主要 Scope：

```text
Global
Script
Local
Private
```

---

# 65. Global Scope

PowerShell Session 启动时就存在。

例如：

```powershell
$Global:Name = "Ema"
```

显式操作：

```text
Global Scope
```

---

# 66. Local Scope

```powershell
$Local:Name = "Ema"
```

代表：

```text
当前 Scope
```

实际上我们平时：

```powershell
$Name = "Ema"
```

通常就是在当前 Scope 创建或赋值。

---

# 67. 函数会产生子 Scope

例如：

```powershell
$name = "outside"

function Test-Scope {
    $name
}

Test-Scope
```

函数可以向父 Scope 查找变量，所以能读到：

```text
outside
```

PowerShell 查找变量时，会从当前 Scope 开始向父 Scope 搜索。

---

# 68. 但是修改是另一回事

例如：

```powershell
$name = "outside"

function Test-Scope {
    $name = "inside"
}

Test-Scope

$name
```

外面的 `$name` 仍然是：

```text
outside
```

原因是，在子 Scope 中对变量赋新值时，PowerShell 通常会在当前 Scope 创建该变量，从而遮蔽父 Scope 中同名变量，而不是直接修改父 Scope。

可以理解：

```text
Global name = outside

        ↓

Function Scope
name = inside

        ↓

两个不同 Scope 中的变量
```

---

# 69. 显式修改 Global

```powershell
$name = "outside"

function Test-Scope {
    $Global:name = "inside"
}

Test-Scope

$name
```

现在得到：

```text
inside
```

不过：

> 正式函数中尽量避免随意修改 Global 状态。

后面学习函数时会详细讨论。

# 70. Script Scope

脚本：

```text
deploy.ps1
```

执行时有自己的：

```text
Script Scope
```

可以：

```powershell
$Script:Config
```

显式声明脚本级变量。

PowerShell 官方说明，脚本中创建的变量默认局限于脚本 Scope；如果脚本通过 dot sourcing 执行，则作用域行为不同。

# 71. `??` Null-coalescing

PowerShell 7 提供：

```powershell
??
```

Null-coalescing 语法。它属于 PowerShell 操作符体系。

例如：

```powershell
$name = $null

$result = $name ?? "Unknown"
```

结果：

```text
Unknown
```

如果：

```powershell
$name = "Ema"
```

则：

```powershell
$name ?? "Unknown"
```

得到：

```text
Ema
```

注意：

```text
??
```

判断的是：

```text
$null
```

不是一般意义上的：

```text
falsey
```

所以它不是 JavaScript：

```text
||
```

的直接替代品。

---

# 72. `??=`

Null-coalescing assignment：

```powershell
$name ??= "Unknown"
```

意思：

```text
如果 $name 是 $null
    ↓
赋值 "Unknown"
```

`??=` 是 PowerShell 的 compound assignment operator 之一。

例如：

```powershell
$configPath = $null

$configPath ??= ".\config.json"
```

---

# 73. 三元表达式

PowerShell 7.0 引入了：

```powershell
condition ? trueValue : falseValue
```

语法与 C# 风格类似。

例如：

```powershell
$port = 8080

$status =
    ($port -eq 8080) ?
        "default" :
        "custom"
```

结果：

```text
default
```

---

# 74. 一个实用例子

```powershell
$environment = "prod"

$logLevel =
    ($environment -eq "prod") ?
        "INFO" :
        "DEBUG"
```

这种简单：

```text
if / else value expression
```

使用三元运算很合适。

复杂逻辑仍建议：

```powershell
if (...) {

}
elseif (...) {

}
else {

}
```

复合赋值：

# 97. 本课最核心的五句话

第一：

> **PowerShell 变量默认没有固定类型约束，真正的类型来自变量当前保存的 .NET 对象。**

第二：

> **PowerShell 在混合类型操作中经常根据左操作数的类型转换右操作数。**

第三：

> **当比较运算符左边是 Collection 时，`-eq` 等运算符可能返回匹配元素，而不是 Boolean。**

第四：

> **`-contains` / `-in` 才是明确询问“集合中有没有这个值”的 Boolean containment operator。**

第五：

> **检查 Null 时把 `$null` 放左边。**

这五句话如果真正理解了，就已经避开了 PowerShell 初学阶段一大半很隐蔽的坑。

本课主要依据以下 Microsoft Learn PowerShell 7.6 官方资料：

* `about_Variables`：变量、松散类型、类型约束与 Scope。
* `about_Type_Conversion`：显式/隐式类型转换以及左操作数驱动转换。
* `about_Numeric_Literals`：数字 Literal、二进制/十六进制和 KB/MB/GB multiplier。
* `about_Arithmetic_Operators`：算术、String/Array/Hashtable 的 `+` 行为。
* `about_Comparison_Operators`：`-eq`、`-like`、`-match`、`-contains`、`-in` 与集合比较。
* `about_Type_Operators`：`-is`、`-isnot`、`-as`。
* `about_Booleans`：Scalar 和 Collection 到 Boolean 的转换规则。
* `about_Logical_Operators`：`-and`、`-or`、`-xor`、`-not` 与短路执行。
* `about_Operator_Precedence`：PowerShell 运算符优先级。
* `about_Arrays`：Array、`@()`、索引和集合行为。
* `about_Hash_Tables`：Hashtable 与 `[ordered]`。
* `about_PSCustomObject`：`[pscustomobject]` 对象创建。
* `about_Scopes`：Global、Script、Local 与 Parent/Child Scope。
* `about_Assignment_Operators`：`=`, `+=`, `-=`, `??=` 等赋值操作。
* `about_If`：PowerShell 7 的三元表达式。
* PSScriptAnalyzer `PossibleIncorrectComparisonWithNull`：为什么 `$null` 应置于比较符左侧。
