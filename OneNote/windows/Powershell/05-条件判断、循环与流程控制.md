---

# 1. `if`

最基本的：

```powershell
$port = 8080

if ($port -eq 8080) {
    "Default port"
}
```

完整结构：

```powershell
if (<condition1>) {
    # ...
}
elseif (<condition2>) {
    # ...
}
else {
    # ...
}
```

PowerShell 会依次测试条件，一旦某个分支成立，就执行对应代码并结束整个 `if` 结构。

---

# 2. `if` 的条件不一定非得是 Boolean

这是上一课内容在控制流中的真正应用。

例如：

```powershell
if ("hello") {
    "True"
}
```

会执行。

因为：

```text
非空 String
→ True
```

而：

```powershell
if ("") {
    "True"
}
else {
    "False"
}
```

得到：

```text
False
```

PowerShell 可以隐式把许多对象转换成 Boolean：

```text
$null       → False
""          → False
0           → False
非空 String → True
普通对象    → True
```

集合还有自己的特殊转换规则。

---

# 3. 一个非常 PowerShell 的条件

例如：

```powershell
if (Get-Process -Name java -ErrorAction SilentlyContinue) {
    "Java is running"
}
```

为什么可以？

因为：

```text
Get-Process
    ↓
没有结果
    ↓
False

或者

Process Object
    ↓
True
```

所以 PowerShell 里经常能看到：

```powershell
if (Test-Path $path) {
    ...
}
```

甚至：

```powershell
if ($object) {
    ...
}
```

---

# 4. 不过要小心集合

例如：

```powershell
$result = @(0)

if ($result) {
    "TRUE"
}
else {
    "FALSE"
}
```

结果：

```text
FALSE
```

因为单元素集合的 Boolean 值取决于那个唯一元素。

但：

```powershell
$result = @(0, 0)
```

却：

```text
TRUE
```

因为包含两个及以上元素的集合会被视为 True。

所以不要随便把：

```powershell
if ($collection)
```

理解成：

```text
collection.Count > 0
```

语义并不完全一样。

如果你真的检查数量：

```powershell
if ($collection.Count -gt 0) {
    ...
}
```

通常更明确。

---

# 5. 多条件判断

例如：

```powershell
$environment = "prod"
$port = 8080

if (
    $environment -eq "prod" -and
    $port -eq 8080
) {
    "Production service"
}
```

推荐复杂条件加括号，使意图更明确：

```powershell
if (
    ($environment -eq "prod") -and
    ($port -ge 8000)
) {
    ...
}
```

---

# 6. Guard Clause

实际脚本里很推荐这种写法：

```powershell
if (-not (Test-Path $configPath)) {
    return
}

# 正常逻辑
```

而不是：

```powershell
if (Test-Path $configPath) {

    # 一大坨代码

}
```

这种：

```text
发现异常条件
↓
尽早离开
```

通常称为：

```text
Guard Clause
```

后面写函数时会大量使用。

# 7. `switch`

如果出现：

```powershell
if ($status -eq "Running") {
}
elseif ($status -eq "Stopped") {
}
elseif ($status -eq "Paused") {
}
elseif (...) {
}
```

就可以考虑：

```powershell
switch ($status) {

    "Running" {
        "Service running"
    }

    "Stopped" {
        "Service stopped"
    }

    "Paused" {
        "Service paused"
    }

    default {
        "Unknown"
    }
}
```

官方文档将 `switch` 描述为处理多个条件的一种更简洁方式。

---

# 8. PowerShell `switch` 和 Java 最大的区别

Java：

```java
switch (value) {
    case 1:
        ...
        break;

    case 2:
        ...
        break;
}
```

很多人因此潜意识认为：

> 一个值命中一个 case。

但 PowerShell **不是这样**。

例如：

```powershell
switch (3) {

    3 {
        "first"
    }

    3 {
        "second"
    }
}
```

结果：

```text
first
second
```

PowerShell 会继续测试后面的条件。

如果一个输入匹配多个条件：

> 所有匹配条件对应的动作都可能执行。

---

# 9. 如果只想匹配第一个

使用：

```powershell
break
```

例如：

```powershell
switch ($status) {

    "Running" {
        "Running"
        break
    }

    "Stopped" {
        "Stopped"
        break
    }

    default {
        "Unknown"
    }
}
```

这里：

```text
break
↓
离开整个 switch
```

官方明确说明，`break` 会停止 `switch` 处理并退出整个 `switch`。

---

# 10. `switch` 默认比较

默认情况下：

```powershell
switch ("PROD") {
    "prod" {
        "Matched"
    }
}
```

可以匹配。

因为普通 `switch`：

```text
默认精确匹配
+
默认忽略大小写
```

等价于使用 `-Exact` 的匹配模式。

---

# 11. `switch` 有一个非常重要的坑

PowerShell 官方特别提醒：

> `switch` 在进行普通匹配时，会把输入值和比较值转换成字符串。

所以它和：

```powershell
$value -eq something
```

并不总有完全相同的类型比较行为。

如果类型非常重要，推荐：

```powershell
switch ($value) {

    { $_ -is [int] } {
        "Integer"
    }

    { $_ -is [string] } {
        "String"
    }
}
```

这里使用 ScriptBlock：

```powershell
{
    $_ -is [int]
}
```

直接返回 Boolean，就不会依赖普通字符串匹配。

---

# 12. `switch` 中也有 `$_`

例如：

```powershell
switch (10) {

    { $_ -gt 5 } {
        "$_ > 5"
    }
}
```

这里：

```powershell
$_
```

代表：

```text
当前正在被 switch 检查的输入值
```

和 Pipeline 里的 `$_` 思想很接近。

---

# 13. `switch` 可以直接处理数组

这是 PowerShell `switch` 很厉害的地方。

```powershell
switch (1, 2, 3, 4, 5) {

    { $_ % 2 -eq 0 } {
        "$_ is even"
    }

    { $_ % 2 -ne 0 } {
        "$_ is odd"
    }
}
```

PowerShell 会：

```text
1
↓
检查全部条件

2
↓
检查全部条件

3
↓
检查全部条件

...
```

如果 test expression 返回多个值，`switch` 会按照顺序逐个处理。

---

# 14. `continue` 在 `switch` 中非常特别

例如：

```powershell
switch (1, -1, 2, -2, 3) {

    { $_ -lt 0 } {
        continue
    }

    default {
        $_
    }
}
```

结果：

```text
1
2
3
```

这里：

```text
continue
```

不是退出整个 `switch`。

而是：

```text
停止处理当前输入
↓
继续处理下一个输入
```

PowerShell 官方对此有明确规定。

所以：

```text
break
```

与：

```text
continue
```

在 `switch` 里的区别：

```text
break
↓
整个 switch 结束

continue
↓
跳到下一个输入值
```

---

# 15. `switch -Wildcard`

例如：

```powershell
switch -Wildcard ("application-prod.yml") {

    "*.yml" {
        "YAML"
    }

    "application-*" {
        "Application config"
    }
}
```

结果会输出：

```text
YAML
Application config
```

因为两个 Pattern 都匹配。

记住：

> PowerShell `switch` 没有自动 break。

`-Wildcard` 使用 PowerShell wildcard 匹配规则。

---

# 16. `switch -Regex`

例如：

```powershell
$url = "https://example.com"

switch -Regex ($url) {

    '^https://' {
        "HTTPS URL"
        break
    }

    '^http://' {
        "HTTP URL"
        break
    }
}
```

官方 `switch -Regex` 使用正则匹配，而且匹配成功时：

```powershell
$Matches
```

也可以使用。

例如：

```powershell
switch -Regex ("server-8080") {

    '^server-(\d+)$' {
        "Port = $($Matches[1])"
    }
}
```

---

# 17. `switch -File`

这个功能很有 PowerShell 味道：

```powershell
switch -File .\application.log {

    "ERROR*" {
        $_
    }
}
```

`switch -File` 会：

```text
读取文件
↓
一行一行处理
↓
每一行成为 switch 输入
```

官方说明 `-File` 一次读取一个文件，并逐行交给 `switch` 进行匹配。

配合 Regex：

```powershell
switch -Regex -File .\application.log {

    'ERROR|Exception' {
        $_
    }
}
```

已经可以做简单日志分析了。

---

# 18. `foreach`

基本结构：

```powershell
foreach ($item in $collection) {

}
```

例如：

```powershell
$ports = 8080, 8081, 9000

foreach ($port in $ports) {
    "Checking $port"
}
```

PowerShell 会自动创建 `$port`，每次迭代把 Collection 中下一个元素赋给它。

---

# 19. 遍历对象

例如：

```powershell
foreach ($process in Get-Process) {

    $process.ProcessName
}
```

这里：

```powershell
$process
```

就是完整的：

```text
System.Diagnostics.Process
```

对象。

所以：

```powershell
$process.Id
$process.ProcessName
$process.WorkingSet64
```

都能使用。

官方 `foreach` 文档也专门以 `Get-ChildItem` 返回的对象集合举例。

---

# 20. `foreach` 和 `ForEach-Object`

第三课学习过：

```powershell
Get-Process |
    ForEach-Object {
        $_.ProcessName
    }
```

现在又有：

```powershell
foreach ($process in Get-Process) {
    $process.ProcessName
}
```

两个都能完成任务。

但它们不是一回事。

---

# 21. `foreach` 是语言结构

```powershell
foreach ($item in $items) {

}
```

属于 PowerShell Language Construct。

而：

```powershell
ForEach-Object
```

是 Cmdlet。

因此：

```text
foreach
    ↓
Collection-oriented control flow

ForEach-Object
    ↓
Pipeline-oriented processing
```

---

# 22. 怎么选？

如果代码天然就是 Pipeline：

```powershell
Get-Process |
    Where-Object WorkingSet64 -gt 500MB |
    ForEach-Object {
        ...
    }
```

使用：

```text
ForEach-Object
```

很自然。

如果代码有：

```text
复杂 if
continue
break
多个步骤
```

例如：

```powershell
foreach ($service in $services) {

    if (-not $service.Enabled) {
        continue
    }

    if ($service.Port -lt 1) {
        continue
    }

    # 多步业务逻辑
}
```

那么：

```text
foreach
```

通常更容易读。

---

# 23. `continue`

在普通循环中：

```powershell
foreach ($number in 1..5) {

    if ($number -eq 3) {
        continue
    }

    $number
}
```

输出：

```text
1
2
4
5
```

`continue`：

```text
终止当前 iteration
↓
直接进入下一轮
```

官方定义为：无 Label 的 `continue` 会回到最内层循环顶部，继续下一次迭代。

---

# 24. `break`

例如：

```powershell
foreach ($number in 1..10) {

    if ($number -eq 5) {
        break
    }

    $number
}
```

结果：

```text
1
2
3
4
```

`break`：

```text
立刻退出当前循环
```

然后继续执行循环后面的代码。

---

# 25. `for`

语法和 Java 非常像：

```powershell
for (
    $i = 0
    $i -lt 10
    $i++
) {
    $i
}
```

传统写法：

```powershell
for ($i = 0; $i -lt 10; $i++) {
    $i
}
```

结构：

```text
Init
↓
Condition
↓
Body
↓
Repeat
↓
Condition
...
```

PowerShell 官方将 `for` 定义为：只要条件继续求值为 True，就持续运行代码块。

---

# 26. 什么时候应该使用 `for`？

官方文档也给了一个很好用的经验：

如果：

```text
我要遍历整个 Collection
```

通常首先考虑：

```powershell
foreach
```

而：

```text
我需要 Index
我需要特殊步长
我不想处理全部元素
```

则：

```powershell
for
```

更合适。

例如：

```powershell
$servers = @(
    "server01"
    "server02"
    "server03"
)

for ($i = 0; $i -lt $servers.Count; $i++) {

    "$i -> $($servers[$i])"
}
```

---

# 27. 特殊步长

```powershell
for ($i = 0; $i -le 20; $i += 2) {
    $i
}
```

：

```text
0
2
4
...
20
```

这就是 `for` 比 `foreach` 灵活的地方之一。

---

# 28. 无限循环

PowerShell：

```powershell
for (;;) {

}
```

是合法的无限循环。

当然，也可以：

```powershell
while ($true) {

}
```

实际代码中一定要确保有：

```powershell
break
```

或者可靠的终止条件。

---

# 29. `while`

基本语法：

```powershell
while (<condition>) {

}
```

例如：

```powershell
$i = 0

while ($i -lt 5) {

    $i
    $i++
}
```

输出：

```text
0
1
2
3
4
```

`while`：

> 在进入循环体之前检查条件。

因此条件一开始就是 False：

```powershell
while ($false) {
    "hello"
}
```

一次也不会执行。

---

# 30. `while` 很适合状态驱动

例如：

```powershell
$retry = 0

while ($retry -lt 3) {

    "Attempt $retry"

    $retry++
}
```

以后可以发展成：

```text
请求 API
↓
失败
↓
重试
↓
达到上限
↓
停止
```

---

# 31. `do while`

```powershell
do {

    # Body

} while (<condition>)
```

最大的区别：

> Body 至少执行一次。

因为 Condition 在 Body 后面才检查。

例如：

```powershell
$i = 100

do {

    $i

} while ($i -lt 10)
```

即使：

```text
100 < 10
```

是 False，

仍然输出：

```text
100
```

一次。

---

# 32. `do until`

PowerShell 还有：

```powershell
do {

} until (<condition>)
```

语义：

```text
只要 Condition 仍然 False
↓
继续循环

Condition 变 True
↓
停止
```

官方对此区分得很明确：

```text
do while
→ 条件为 True 时继续

do until
→ 条件为 False 时继续
```

二者都至少运行一次。

---

# 33. 一个很自然的例子

等待某个文件出现：

```powershell
do {

    Start-Sleep -Seconds 1

} until (
    Test-Path ".\ready.txt"
)
```

读起来就是：

> 不断等待，直到文件存在。

而：

```powershell
while (-not (Test-Path ".\ready.txt")) {
    Start-Sleep -Seconds 1
}
```

语义也一样。

---

# 34. 应该用哪个循环？

可以先建立这张表：

| 需求             | 优先考虑             |
| -------------- | ---------------- |
| 遍历 Collection  | `foreach`        |
| Pipeline 逐对象处理 | `ForEach-Object` |
| 需要 Index       | `for`            |
| 按条件重复          | `while`          |
| 至少执行一次         | `do while`       |
| 一直运行直到条件成立     | `do until`       |

---

# 35. 嵌套循环

例如：

```powershell
foreach ($hostName in @("server01", "server02")) {

    foreach ($port in @(80, 443)) {

        "$hostName : $port"
    }
}
```

得到：

```text
server01 : 80
server01 : 443
server02 : 80
server02 : 443
```

---

# 36. 嵌套循环的 `break`

默认：

```powershell
break
```

只退出：

```text
当前最内层控制结构
```

例如：

```powershell
foreach ($server in $servers) {

    foreach ($port in $ports) {

        if (...) {
            break
        }
    }
}
```

这里只退出：

```text
inner foreach
```

外面的 server loop 仍然继续。

---

# 37. PowerShell 支持 Label

这是个非常实用但很多教程不讲的功能。

```powershell
:serverLoop foreach ($server in $servers) {

    foreach ($port in $ports) {

        if (...) {
            break serverLoop
        }
    }
}
```

这里：

```text
break serverLoop
```

会直接退出指定的：

```text
serverLoop
```

而不仅仅是最内层循环。

官方 `break` 和 `continue` 都支持 Label。

---

# 38. Label 的语法

Label：

```powershell
:outer
```

必须直接放在循环结构之前：

```powershell
:outer foreach ($a in $items) {

}
```

然后：

```powershell
break outer
```

或者：

```powershell
continue outer
```

---

# 39. `continue label`

例如：

```powershell
:serverLoop foreach ($server in $servers) {

    foreach ($port in $ports) {

        if ($port -eq 8080) {
            continue serverLoop
        }

        "Testing $server:$port"
    }
}
```

意味着：

```text
终止当前 port loop
↓
回到外层 serverLoop
↓
处理下一个 Server
```

官方定义允许 `continue` 把控制转移到指定的 enclosing loop。

---

# 40. 现在来到最容易误解的：`return`

Java：

```java
return result;
```

通常理解为：

```text
函数只返回 result
```

但 PowerShell：

```powershell
return
```

主要含义是：

> 离开当前 Function / Script / ScriptBlock Scope。

而 PowerShell 的输出机制本身就可以产生“返回值”。

---

# 41. PowerShell 函数根本不需要 `return`

例如：

```powershell
function Get-Answer {

    42
}
```

执行：

```powershell
$result = Get-Answer
```

：

```text
42
```

根本没写：

```powershell
return
```

因为 PowerShell 会把正常输出到成功输出流的结果作为函数输出。

---

# 42. 这是一个超级大坑

看：

```powershell
function Get-Result {

    "Starting calculation..."

    $result = 42

    return $result
}
```

然后：

```powershell
$value = Get-Result
```

你可能以为：

```powershell
$value
```

等于：

```text
42
```

实际上：

```text
Starting calculation...
42
```

两样东西都会进入 `$value`。

因为这一行：

```powershell
"Starting calculation..."
```

本身产生了 Output。

官方文档专门用几乎相同的例子提醒这一点。

---

# 43. PowerShell 函数最重要的思维

不是：

```text
return 决定返回什么
```

而是：

```text
函数执行过程中
所有写入 Success Output Stream 的对象
        ↓
组成函数输出
```

所以后面写函数时，要特别小心：

```powershell
"debug"
```

这种裸字符串。

它不是普通 Debug Message。

它可能成为：

```text
业务返回值的一部分
```

---

# 44. 调试信息不要污染输出

例如以后更推荐：

```powershell
Write-Verbose "Starting calculation"
```

或者明确使用：

```powershell
Write-Information "Starting calculation"
```

而不要：

```powershell
"Starting calculation"
```

官方 `return` 文档也建议将信息性消息放到 Information Stream，而不是让其进入普通输出。

---

# 45. `return` 更适合干什么？

很适合：

```text
提前退出函数
```

例如：

```powershell
function Test-ServiceConfig {

    if ($null -eq $config) {

        return
    }
```

# 48. `break` / `continue` / `return` 对照

这是本课很重要的一张表：

| 关键字        | 作用                                     |
| ---------- | -------------------------------------- |
| `continue` | 跳过当前 iteration                         |
| `break`    | 离开当前 loop / switch                     |
| `return`   | 离开当前 function/script/scriptblock scope |

例如：

```text
continue
↓
这轮不要了

break
↓
整个循环不要了

return
↓
这个函数/脚本块都不要继续了
```

# 54. 加入重试

```powershell
foreach ($service in $services) {

    if (-not $service.Enabled) {
        continue
    }

    $maxRetries = 3
    $attempt = 0
    $available = $false

    while (
        -not $available -and
        $attempt -lt $maxRetries
    ) {

        $attempt++

        $available = Test-Connection `
            -TargetName $service.Host `
            -TcpPort $service.Port `
            -Quiet

        if (-not $available) {
            Start-Sleep -Seconds 1
        }
    }

    [PSCustomObject]@{
        Name     = $service.Name
        Available = $available
        Attempts = $attempt
    }
}
```

现在：

```text
foreach
↓
处理多个 Service

while
↓
每个 Service 重试

if
↓
决定是否继续

PSCustomObject
↓
返回结构化结果
```

已经是很正规的自动化代码了。

# 66. 本课最重要的 Java → PowerShell 差异

### 差异一

Java/C#：

```text
switch 通常围绕一个 case 流程工作
```

PowerShell：

```text
switch 可以匹配多个条件
```

除非：

```powershell
break
```

---

### 差异二

PowerShell：

```powershell
switch ($array)
```

会直接逐元素处理 Collection。

---

### 差异三

`switch` 默认比较会进行 String Conversion。

类型敏感逻辑更推荐：

```powershell
switch ($value) {

    { $_ -is [int] } {
    }
}
```

---

### 差异四

`continue` 在：

```powershell
switch
```

里面表示：

```text
跳过当前输入值
继续处理下一个输入
```

---

### 差异五

PowerShell：

```powershell
return 42
```

并不意味着：

> 函数只可能输出 42。

函数前面产生的普通 Success Output 也属于函数输出。

# 68. 选择控制结构的思维

面对需求：

```text
我要做判断
↓
if

我要匹配很多分类
↓
switch

我要处理整个集合
↓
foreach

我要在 Pipeline 中处理对象
↓
ForEach-Object

我要按 Index 或步长循环
↓
for

我要只要条件成立就继续
↓
while

我要至少执行一次
↓
do

我要跳过当前循环
↓
continue

我要退出循环
↓
break

我要退出函数 / ScriptBlock
↓
return
```

# 69. 本课最值得记住的四句话

> **`switch` 可以匹配多个分支，并不会像很多语言那样自动在第一次匹配后结束。**

> **`continue` 在普通 Loop 中跳到下一次迭代，在 `switch` 中则跳到下一个输入值。**

> **`do while` 和 `do until` 至少运行一次，而普通 `while` 可能一次也不运行。**

> **PowerShell 函数的输出不是只由 `return` 决定；函数执行过程中产生的普通输出也会成为返回结果。**
