# WSL2 配置

> [!abstract]
> WSL 2 有两套核心配置：
>
> * `.wslconfig`：配置整个 WSL 2 VM
> * `/etc/wsl.conf`：配置某一个 Linux Distribution
>
> 最重要的区别就是：**全局 VM 配置 vs 单发行版配置**。

Microsoft 当前也推荐优先通过 Windows 的 **WSL Settings** 修改全局 WSL 设置；`.wslconfig` 仍然是对应的配置文件方式。

---

# 1. `.wslconfig` 与 `wsl.conf`

| 配置           | 位置                         | 作用域                   | 主要负责                         |
| ------------ | -------------------------- | --------------------- | ---------------------------- |
| `.wslconfig` | `%UserProfile%\.wslconfig` | 所有 WSL 2 Distribution | CPU、RAM、Swap、网络、VHD 等        |
| `wsl.conf`   | `/etc/wsl.conf`            | 当前 Distribution       | systemd、挂载、DNS、Interop、默认用户等 |

例如：

```text
Windows
│
├── C:\Users\<user>\.wslconfig
│       ↓
│   整个 WSL 2 VM
│
└── WSL 2
    ├── Ubuntu
    │   └── /etc/wsl.conf
    │
    └── Debian
        └── /etc/wsl.conf
```

`.wslconfig` 是全局 WSL 2 VM 配置，而 `/etc/wsl.conf` 只影响所在的 Distribution。

---

# 2. 配置什么时候生效？

修改配置后，WSL 必须真正停止并重新启动。

最直接：

`wsl --shutdown`

然后重新启动：

`wsl`

Microsoft 文档中还有所谓的 **8 秒规则**：关闭终端并不意味着 WSL VM 已立即结束，它可能继续运行几秒。实际开发中直接执行 `wsl --shutdown` 更确定。

> [!warning]
> `wsl --shutdown` 会停止所有正在运行的 WSL Distribution。

如果只需要停止某个 Distribution：

`wsl --terminate Ubuntu`

---

# 3. `.wslconfig`

路径：

`C:\Users\<WindowsUser>\.wslconfig`

也可以写作：

`%UserProfile%\.wslconfig`

它默认可能不存在，需要时自行创建。

基本结构：

```ini
[wsl2]
memory=8GB
processors=8
swap=4GB
networkingMode=mirrored
```

`.wslconfig` 使用类似 INI 的配置格式。

---

# 4. `memory`

用于限制整个 WSL 2 VM 可以使用的最大内存：

```ini
[wsl2]
memory=8GB
```

当前默认值为 Windows 总内存的 `50%`。

例如：

Windows 有 `32GB RAM`：

默认最大值大约为 `16GB`。

如果配置：

```ini
[wsl2]
memory=12GB
```

则整个 WSL 2 VM 最大使用约 `12GB`。

---

## 是否应该限制内存？

普通开发环境不一定需要修改默认值。

以下情况可以考虑限制：

* WSL 经常占用过多 RAM
* 同时运行 IDE、浏览器、大型 Windows 软件
* WSL 中运行大量容器
* AI / Java 服务占用大量内存
* 希望明确划分 Windows 与 Linux 资源

但不要设置得过低，否则：

* JVM
* Docker
* Node.js build
* Python AI workload
* 数据库

都可能受到影响。

---

# 5. `processors`

限制 WSL 2 可以使用的逻辑 CPU：

```ini
[wsl2]
processors=8
```

默认情况下，WSL 2 可以使用 Windows 的全部逻辑处理器。

例如 Windows：

`16 Logical Processors`

配置：

```ini
processors=8
```

WSL 中：

```bash
nproc
```

通常会看到 `8`。

---

# 6. `swap`

设置 WSL 2 Swap：

```ini
[wsl2]
swap=4GB
```

当前默认 Swap 大小为 Windows 内存大小的 `25%`，向上取整到 GB。设置 `swap=0` 可以关闭 Swap。

例如：

```ini
swap=0
```

表示禁用 Swap。

通常不建议为了所谓“性能优化”直接关闭 Swap。

---

# 7. `swapFile`

可以指定 Swap VHD 的位置：

```ini
[wsl2]
swap=8GB
swapFile=D:\\WSL\\swap.vhdx
```

注意这里使用的是 **Windows Path**。

反斜杠需要转义：

`D:\\WSL\\swap.vhdx`

当前默认 Swap 文件位于 Windows 临时目录中的 `swap.vhdx`。

---

# 8. `networkingMode`

控制 WSL 2 网络模式：

```ini
[wsl2]
networkingMode=mirrored
```

当前可用模式包括：

* `nat`
* `mirrored`
* `virtioproxy`
* `none`

旧的 `bridged` 已被标记为 deprecated。

默认：

`NAT`

现代 Windows 11 开发环境通常可以考虑：

```ini
[wsl2]
networkingMode=mirrored
```

具体网络行为见：

[[WSL2网络]]

---

# 9. `localhostForwarding`

```ini
[wsl2]
localhostForwarding=true
```

用于 NAT 模式下，让 WSL 中监听的端口可以通过 Windows：

`localhost:<port>`

访问。

默认值：

`true`

在 `networkingMode=mirrored` 时，这个配置会被忽略。

---

# 10. `dnsTunneling`

```ini
[wsl2]
dnsTunneling=true
```

让 WSL DNS 请求通过 WSL 与 Windows 之间的虚拟化通道处理。

默认：

`true`

它主要改善：

* VPN
* 企业 DNS
* 内网域名
* 复杂 Windows 网络环境

下的 DNS 兼容性。

一般保持默认即可。

---

# 11. `autoProxy`

```ini
[wsl2]
autoProxy=true
```

让 WSL 使用 Windows 的 HTTP Proxy 信息。

默认：

`true`。

如果公司环境使用：

* HTTP Proxy
* HTTPS Proxy
* 企业代理

这个配置尤其有用。

---

# 12. `firewall`

```ini
[wsl2]
firewall=true
```

允许 Windows Firewall 和 Hyper-V Firewall 规则过滤 WSL 网络流量。

默认：

`true`。

一般不要关闭。

---

# 13. `defaultVhdSize`

WSL Distribution 的 Linux 文件系统位于 VHDX 中。

可以设置新 Distribution 的默认最大 VHD 大小：

```ini
[wsl2]
defaultVhdSize=512GB
```

当前默认最大值为 `1TB`。

注意：

> `1TB` 是 VHD 最大容量，不代表 WSL 安装后立即占用 1TB。

磁盘相关内容放到：

[[WSL2磁盘管理]]

---

# 14. 一个实用的 `.wslconfig`

如果是现代 Windows 11 开发环境，可以从下面这种配置开始：

```ini
[wsl2]
memory=12GB
processors=8
swap=4GB

networkingMode=mirrored
dnsTunneling=true
autoProxy=true
firewall=true
```

其中 `memory` 和 `processors` 必须根据机器配置调整。

例如高配开发机也可以完全不限制：

```ini
[wsl2]
networkingMode=mirrored
dnsTunneling=true
autoProxy=true
```

让 WSL 使用默认资源策略。

---

# 15. 不建议盲目配置的参数

`.wslconfig` 还有：

* `kernel`
* `kernelModules`
* `kernelCommandLine`
* `nestedVirtualization`
* `debugConsole`
* `safeMode`

这些属于特殊场景。

例如：

```ini
kernel=C:\\Kernel\\bzImage
```

表示使用自定义 Linux Kernel。

普通开发环境没有必要修改。

> [!tip]
> WSL 配置不是越多越好。
>
> 没有明确需求的参数，保留默认值通常更合理。

---

# 16. Experimental 配置

`.wslconfig` 还支持：

```ini
[experimental]
```

例如：

```ini
[experimental]
autoMemoryReclaim=dropCache
sparseVhd=true
```

这些属于实验性配置，行为和默认值可能随着 WSL 更新改变。当前 Microsoft 文档仍将它们标记为 experimental。

因此知识库里可以记录，但不建议把实验配置直接复制进所有开发环境。

---

# 17. `autoMemoryReclaim`

用于控制 WSL 自动回收缓存内存：

```ini
[experimental]
autoMemoryReclaim=gradual
```

当前支持：

* `disabled`
* `gradual`
* `dropCache`

Microsoft 当前文档中的默认值是 `dropCache`。

如果没有明确的内存问题，保持默认即可。

---

# 18. `sparseVhd`

```ini
[experimental]
sparseVhd=true
```

让新创建的 VHD 自动使用 sparse 模式。

主要与 WSL 磁盘空间管理有关。

详细放到：

[[WSL2磁盘管理]]

---

# 19. `/etc/wsl.conf`

`wsl.conf` 位于某个 Distribution 内：

`/etc/wsl.conf`

例如 Ubuntu：

```bash
sudo nano /etc/wsl.conf
```

它只影响当前 Ubuntu，而不会修改其他 Distribution。

常见配置结构：

```ini
[boot]

[automount]

[network]

[interop]

[user]
```

---

# 20. `[boot]`

## systemd

现代 Ubuntu 通常已经默认使用 `systemd`。

如果某个 Distribution 需要显式开启：

```ini
[boot]
systemd=true
```

然后：

`wsl --shutdown`

重新进入后检查：

```bash
systemctl status
```

Microsoft 当前 WSL 已正式支持 `systemd`。

详细内容：

[[WSL2-systemd]]

---

## boot command

还可以在 Distribution 启动时执行命令：

```ini
[boot]
command=echo "WSL started"
```

这个命令以 `root` 身份运行。

一般不建议把复杂初始化逻辑都塞到这里。

对于服务管理，应优先考虑 `systemd`。

---

# 21. `[automount]`

控制 Windows Drive 如何挂载到 WSL：

```ini
[automount]
enabled=true
root=/mnt/
mountFsTab=true
```

默认情况下：

`C:\` → `/mnt/c`

`D:\` → `/mnt/d`

其中 `enabled=true`、`mountFsTab=true`，挂载根目录默认是 `/mnt/`。

---

# 22. 修改 Windows Drive 挂载目录

例如：

```ini
[automount]
root=/
```

Windows：

`C:\`

可能变成：

`/c`

而不是：

`/mnt/c`

但没有特殊需求一般不要修改默认路径。

大量脚本和工具默认假设 Windows Drive 位于：

`/mnt/<drive>`

---

# 23. DrvFS Metadata

例如：

```ini
[automount]
options="metadata"
```

开启 Windows 文件上的 Linux Metadata 支持。

可以进一步：

```ini
[automount]
options="metadata,umask=022,fmask=011"
```

这会影响 `/mnt/c` 等 DrvFS 文件的：

* UID
* GID
* Permission
* File Mode

详细原理见：

[[WSL2文件系统]]

当前默认 `metadata` 是关闭状态。

---

# 24. `/etc/fstab`

默认：

```ini
[automount]
mountFsTab=true
```

意味着 WSL 启动时会处理：

`/etc/fstab`

例如可以自动挂载：

* 额外磁盘
* SMB
* 网络文件系统
* 自定义 Mount

因此复杂 Mount 应优先放进 `/etc/fstab`，而不是全部塞进 `wsl.conf`。

---

# 25. `[network]`

常见配置：

```ini
[network]
generateHosts=true
generateResolvConf=true
```

默认两个都是 `true`。

---

## `generateHosts`

控制 WSL 是否自动生成：

`/etc/hosts`

```ini
[network]
generateHosts=false
```

关闭以后可以自行管理 `/etc/hosts`。

一般保持默认。

---

## `generateResolvConf`

控制是否自动生成：

`/etc/resolv.conf`

```ini
[network]
generateResolvConf=false
```

关闭以后可以手动管理 DNS。

但现代 WSL 有 `dnsTunneling`，所以遇到 DNS 问题时不要第一反应就是禁用自动生成。

通常保持：

```ini
[network]
generateResolvConf=true
```

更合理。

---

# 26. 修改 Hostname

```ini
[network]
hostname=dev-wsl
```

然后：

```bash
hostname
```

可以看到：

`dev-wsl`

默认情况下 WSL 使用 Windows Hostname。

---

# 27. `[interop]`

WSL 的一个重要能力是直接运行 Windows 程序：

```bash
explorer.exe .
notepad.exe
powershell.exe
```

由 `interop` 控制。

默认：

```ini
[interop]
enabled=true
appendWindowsPath=true
```

---

# 28. `enabled`

如果：

```ini
[interop]
enabled=false
```

WSL 将禁止直接启动 Windows Process。

例如：

```bash
explorer.exe .
```

将不再正常工作。

一般保持：

`true`

---

# 29. `appendWindowsPath`

默认情况下，WSL 会把部分 Windows `PATH` 加入 Linux `$PATH`。

因此：

```bash
echo $PATH
```

可能看到：

`/mnt/c/Windows/...`

如果不希望 Windows Executable 污染 Linux `PATH`：

```ini
[interop]
appendWindowsPath=false
```

这是一个比较值得了解的高级配置。

例如你希望：

```bash
python
node
git
java
```

严格来自 Linux 环境，而不是意外解析到 Windows 安装版本时，可以考虑关闭。

---

# 30. 检查实际执行的是谁

例如：

```bash
which git
which python
which node
which java
```

推荐 WSL 项目使用 Linux Toolchain，例如：

`/usr/bin/git`

而不是意外执行：

`/mnt/c/.../git.exe`

---

# 31. `[user]`

可以设置 Distribution 默认用户：

```ini
[user]
default=ema
```

以后执行：

`wsl -d Ubuntu`

默认使用：

`ema`

而不是 `root`。

Microsoft 当前文档仍支持通过 `[user] default=...` 设置默认 Distribution 用户。

---

# 32. 一个推荐的 `wsl.conf`

普通开发环境通常不需要很多自定义：

```ini
[boot]
systemd=true

[automount]
enabled=true
mountFsTab=true

[network]
generateHosts=true
generateResolvConf=true

[interop]
enabled=true
appendWindowsPath=true

[user]
default=ema
```

实际上很多字段都是默认值。

因此真正的文件可能只需要：

```ini
[boot]
systemd=true

[user]
default=ema
```

> [!tip]
> 不要为了“配置完整”把所有默认值重新写一遍。
>
> 只声明真正需要修改的配置。

---

# 33. 仆更推荐的配置哲学

例如你的机器完全没有资源问题：

不要写：

```ini
memory=8GB
processors=4
swap=0
```

仅仅因为某篇博客这么配置。

让默认资源策略工作即可。

如果你真正遇到：

`WSL 占用 RAM 太高`

再配置：

```ini
[wsl2]
memory=12GB
```

如果遇到：

`WSL → Windows 网络麻烦`

再考虑：

```ini
networkingMode=mirrored
```

如果需要严格 Linux Toolchain：

```ini
[interop]
appendWindowsPath=false
```

也就是说：

> **配置应该解决具体问题，而不是为了配置而配置。**

---

# 34. 配置排错

修改 `.wslconfig` 后发现没生效：

首先：

```powershell
wsl --shutdown
```

然后重新进入。

查看正在运行的 Distribution：

```powershell
wsl --list --running
```

查看 WSL：

```powershell
wsl --status
wsl --version
```

检查 `.wslconfig`：

```powershell
Get-Content "$env:USERPROFILE\.wslconfig"
```

检查 Linux：

```bash
cat /etc/wsl.conf
```

如果 `.wslconfig` 格式错误，WSL 可能仍然正常启动，但不会应用错误的配置。

# 37. 核心心智模型

```text
C:\Users\<user>\.wslconfig
        │
        ▼
┌─────────────────────────────┐
│          WSL 2 VM           │
│                             │
│ CPU / RAM / Swap / Network  │
│                             │
│   ┌─────────┐ ┌─────────┐   │
│   │ Ubuntu  │ │ Debian  │   │
│   └────┬────┘ └────┬────┘   │
└────────┼────────────┼────────┘
         │            │
         ▼            ▼
 /etc/wsl.conf  /etc/wsl.conf
```

所以直接记：

`Windows VM 层` → `.wslconfig`

`Linux Distro 层` → `/etc/wsl.conf`

# 38. 常用配置速查

## `.wslconfig`

| 配置                    | 作用                    |
| --------------------- | --------------------- |
| `memory`              | 最大 RAM                |
| `processors`          | CPU 数量                |
| `swap`                | Swap 大小               |
| `swapFile`            | Swap VHD 位置           |
| `networkingMode`      | 网络模式                  |
| `localhostForwarding` | NAT localhost 转发      |
| `dnsTunneling`        | DNS Tunnel            |
| `autoProxy`           | Windows Proxy 同步      |
| `firewall`            | Firewall 集成           |
| `defaultVhdSize`      | Distribution VHD 最大容量 |

## `/etc/wsl.conf`

| Section       | 作用                      |
| ------------- | ----------------------- |
| `[boot]`      | systemd / Boot Command  |
| `[automount]` | Windows Drive / fstab   |
| `[network]`   | Hostname / hosts / DNS  |
| `[interop]`   | Windows ↔ Linux Process |
| `[user]`      | 默认 Linux User           |
