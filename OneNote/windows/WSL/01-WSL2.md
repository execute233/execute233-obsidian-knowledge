
# WSL2

> [!abstract] 一句话理解
> **WSL 2 是 Windows 提供的一套 Linux 运行环境。**
>
> 它利用虚拟化技术，在 Windows 中运行真正的 Linux Kernel，让我们可以直接使用 Ubuntu、Bash、Git、Python、Node.js、Docker CLI、systemd 等 Linux 工具。


---

# 第一课：认识 WSL 2

## WSL 是什么？

WSL：

```text
Windows Subsystem for Linux
```

中文：

```text
适用于 Linux 的 Windows 子系统
```

WSL 2 允许我们：

```text
Windows
    │
    ├── Windows 应用
    │
    ├── PowerShell
    │
    ├── VS Code
    │
    └── WSL 2
         │
         └── Linux
              │
              ├── Ubuntu
              ├── Bash
              ├── apt
              ├── Git
              ├── Python
              ├── Node.js
              ├── gcc
              ├── systemd
              └── Linux CLI
```

简单理解：

> **Windows 是宿主操作系统，WSL 2 为我们提供 Linux 开发环境。**

---

# WSL 2 的底层结构

WSL 2 并不是简单模拟几个 Linux 命令。

它真正运行：

```text
Linux Kernel
```

可以建立下面这个心智模型：

```text
┌──────────────────────────────────────┐
│               Windows                │
│                                      │
│   PowerShell          VS Code        │
│                                      │
│          ┌────────────────────┐      │
│          │       WSL 2        │      │
│          │                    │      │
│          │  Lightweight VM    │      │
│          │        │           │      │
│          │        ▼           │      │
│          │   Linux Kernel     │      │
│          │        │           │      │
│          │        ▼           │      │
│          │      Ubuntu        │      │
│          │                    │      │
│          │ bash / apt / git   │      │
│          │ python / node ...  │      │
│          └────────────────────┘      │
│                                      │
└──────────────────────────────────────┘
```

因此 WSL 2 中运行的是一个真正的 Linux Kernel。

但这里的 VM 和我们传统手动创建的 VMware / VirtualBox 虚拟机有所不同。

WSL 2 使用：

```text
Lightweight Utility VM
```

这个虚拟化环境主要由 Windows 和 WSL 自动管理。

通常不需要我们自己：

```text
创建 VM
配置虚拟网卡
配置虚拟磁盘
安装 Linux ISO
管理 VM 开关机
```

这些事情 WSL 会帮我们处理。

---

# WSL 2 与传统虚拟机的区别

传统虚拟机：

```text
Windows
   │
   ▼
VMware / VirtualBox
   │
   ▼
Virtual Machine
   │
   ├── Virtual CPU
   ├── Virtual RAM
   ├── Virtual Disk
   └── Linux
```

通常需要自己管理：

```text
CPU
RAM
Disk
Network
Linux 安装
VM 生命周期
```

WSL 2：

```text
Windows
   │
   ▼
WSL
   │
   ▼
Lightweight Utility VM
   │
   ▼
Linux Kernel
   │
   ▼
Ubuntu / Debian / ...
```

很多底层资源由 Windows 自动管理。

所以 WSL 2 特别适合：

```text
Linux 开发
Web 开发
后端开发
AI 开发
Docker 开发
Linux CLI 学习
DevOps 学习
```

# WSL 2 与 Linux Distribution

这里需要区分两个概念。

## WSL 2

WSL 2 是：

```text
运行 Linux 的基础平台
```

## Distribution

Distribution，简称：

```text
Distro
```

指具体的 Linux 发行版。

例如：

```text
Ubuntu
Debian
Kali Linux
openSUSE
Arch Linux
```

关系可以理解为：

```text
WSL 2
│
├── Ubuntu
├── Debian
└── Kali
```

因此：

> **WSL 2 不是 Ubuntu。**

更加准确地说：

> **Ubuntu 可以运行在 WSL 2 上。**

---

# Distribution 与 Kernel

另外一个很重要的知识点：

```text
Ubuntu
```

并不等于：

```text
Linux Kernel
```

可以简单理解：

```text
Linux Kernel
    │
    ▼
Linux Distribution
    │
    ├── 软件包管理器
    ├── Shell
    ├── GNU 工具
    ├── 默认配置
    └── 软件生态
```

在 WSL 2 中：

```text
WSL 2
    │
    ▼
Linux Kernel
    │
    ▼
Ubuntu
    │
    ├── bash
    ├── apt
    ├── systemd
    └── applications
```

```text
Windows 11
```

# 安装 WSL

首先打开：

```text
PowerShell
```

建议第一次安装时：

```text
以管理员身份运行 PowerShell
```

执行：

```powershell
wsl --install
```

这个命令会安装运行 WSL 所需要的组件，并默认安装 Linux Distribution。

通常默认 Distribution 是：

```text
Ubuntu
```

完成以后根据 Windows 提示进行：

```text
Restart
```

如果系统要求重启，就重新启动 Windows。

---

# 查看可以安装的 Distribution

执行：

```powershell
wsl --list --online
```

简写：

```powershell
wsl -l -o
```

会列出当前可以安装的 Distribution。

例如可能出现：

```text
NAME
Ubuntu
Debian
kali-linux
openSUSE-...
...
```

具体列表由当前 WSL 提供。

---

# 安装指定 Distribution

例如安装 Ubuntu：

```powershell
wsl --install -d Ubuntu
```

安装 Debian：

```powershell
wsl --install -d Debian
```

基本格式：

```powershell
wsl --install -d <Distribution>
```

---

# 检查 WSL

回到 PowerShell：

```powershell
wsl --status
```

可以查看 WSL 的基本状态。

还可以：

```powershell
wsl --version
```

查看当前安装的 WSL 组件版本。

# 查看安装的 Distribution

PowerShell：

```powershell
wsl --list --verbose
```

简写：

```powershell
wsl -l -v
```

可能看到：

```text
  NAME      STATE           VERSION
* Ubuntu    Running         2
```

重点关注：

```text
VERSION
```

这里应该是：

```text
2
```

因为这套课程只使用：

```text
WSL 2
```

---

# STATE

例如：

```text
NAME      STATE      VERSION
Ubuntu    Running    2
```

其中：

```text
Running
```

表示当前 Distribution 正在运行。

也可能看到：

```text
Stopped
```

表示 Distribution 当前已经停止。

# Distribution

如果只有一个 Distribution：

```powershell
wsl
```

通常就会直接进入它。

如果有：

```text
Ubuntu
Debian
```

多个 Distribution，可以设置默认：

```powershell
wsl --set-default Ubuntu
```

简写：

```powershell
wsl -s Ubuntu
```

以后：

```powershell
wsl
```

默认进入 Ubuntu。

# 启动指定 Distribution

例如：

```powershell
wsl -d Ubuntu
```

完整形式：

```powershell
wsl --distribution Ubuntu
```

如果：

```text
Ubuntu
Debian
```

同时存在，就可以：

```powershell
wsl -d Ubuntu
```

或者：

```powershell
wsl -d Debian
```

进入不同系统。

# 从 Home 目录启动 WSL

PowerShell：

```powershell
wsl ~
```

可以让 WSL 从 Linux 用户的 Home 目录启动。

# Windows 文件在 WSL 2 中的位置

Windows：

```text
C:\
```

在 WSL 中通常挂载为：

```text
/mnt/c
```

例如 Windows：

```text
C:\Users\Ema\Downloads
```

在 WSL 中：

```bash
/mnt/c/Users/Ema/Downloads
```

# 一个非常重要的开发原则

> [!important]
> 如果主要使用 Linux 工具开发，项目尽量放在 **WSL 2 的 Linux 文件系统**，而不是 `/mnt/c`。

推荐：

```bash
~/projects
```

例如：

```bash
/home/ema/projects/my-app
```

推荐：

```bash
mkdir -p ~/projects
cd ~/projects
```

然后：

```bash
git clone ...
```

而不是长期把 Linux 项目放：

```bash
/mnt/c/Users/Ema/projects
```

原因主要是：

```text
文件系统性能
文件监听
Linux 权限模型
开发工具兼容性
Docker Bind Mount 性能
```

对于：

```text
Git
npm
pnpm
yarn
Python
uv
pip
Docker
Rust
Go
```

这种会大量访问小文件的开发工具尤其重要。

# 停止一个 Distribution

例如：

```powershell
wsl --terminate Ubuntu
```

表示：

```text
停止 Ubuntu
```

查看：

```powershell
wsl -l -v
```

应该看到：

```text

```

```powershell
wsl
```

就可以再次启动。

# 关闭整个 WSL 2 环境

执行：

```powershell
wsl --shutdown
```

这会关闭当前运行中的 WSL 2 环境。

可以简单理解为：

```text
wsl --terminate Ubuntu
↓
停止一个 Distribution

wsl --shutdown
↓
关闭整个 WSL 运行环境
```

以后我们修改：

```text
.wslconfig
```

时会经常使用：

```powershell
wsl --shutdown
```

# WSL 2 并不需要一直运行

WSL 2 可以按需启动。

例如执行：

```powershell
wsl
```

会启动需要的 Linux 环境。

执行：

```powershell
wsl --shutdown
```

会关闭运行环境。

因此不需要像传统 VM 一样：

```text
启动 VMware
打开 VM
等待完整 Linux Desktop 启动
```

才能使用 Linux CLI。

# WSL 2 使用真正的 Linux 文件系统

WSL 2 的 Linux Distribution 数据并不是简单存在：

```text
C:\Linux\
```

这种普通目录里面。

每个 Distribution 的 Linux 文件系统由虚拟磁盘保存。

核心形式通常是：

```text
ext4.vhdx
```

里面使用：

```text
ext4
```

文件系统。

因此可以粗略理解：

```text
Windows Disk
│
└── ext4.vhdx
     │
     └── ext4
          │
          ├── /
          ├── /home
          ├── /etc
          ├── /usr
          └── /var
```

这个知识之后在：

```text
[[WSL2磁盘管理]]
```

中详细学习。

> [!warning]
> 不要为了修改 Linux 文件而直接手动操作 WSL 内部的 `ext4.vhdx`。
>
> 正常访问 Linux 文件应该通过 WSL、`\\wsl$`、VS Code WSL 等方式。

```text
WSL 2
```

中运行：

```text
FastAPI

```

然后直接使用 Windows 浏览器进行开发。

# `.wslconfig` 与 `wsl.conf`

这是 WSL 2 非常重要的一组概念。

名字看起来很像：

```text
.wslconfig

wsl.conf
```

但用途完全不同。

---

## `.wslconfig`

位置在 Windows：

```text
C:\Users\<WindowsUser>\.wslconfig
```

也就是：

```text
%UserProfile%\.wslconfig
```

作用：

```text
配置整个 WSL 2 虚拟环境
```

例如：

```text
Memory
CPU
Swap
Networking
Kernel
```

可以简单理解：

---

## `/etc/wsl.conf`

它存在：

```text
Linux Distribution
```

内部。

路径：

```bash
/etc/wsl.conf
```

作用是：

```text
配置某一个 Linux Distribution
```

例如：

```text
boot
systemd
automount
interop
default user
```

可以理解：

```text
WSL 2
│
├── Ubuntu
│   └── /etc/wsl.conf
│
└── Debian
    └── /etc/wsl.conf
```

所以：

```text
.wslconfig
↓
全局 WSL 2

/etc/wsl.conf
↓
单个 Distribution
```

# 第一课常见问题

## WSL 2 是虚拟机吗？

底层使用虚拟化，并运行一个轻量级 Utility VM。

但使用体验与传统 VMware / VirtualBox 虚拟机不同：

```text
底层
↓
有虚拟化

使用体验
↓
高度集成进 Windows
```

所以更准确的理解是：

> WSL 2 使用轻量级虚拟化运行 Linux Kernel，但这个虚拟环境主要由 WSL 自动管理。

---

## Ubuntu 是虚拟机吗？

不应该简单理解成：

```text
Ubuntu = 一台传统 VM
```

更合适的是：

```text
Ubuntu
↓
WSL Distribution
↓
运行在 WSL 2 环境中
```

---

## WSL 2 可以当 Linux 学吗？

可以。

尤其适合学习：

```text
Linux Shell
文件系统
权限
用户
软件包管理
Git
SSH
systemd
Nginx
数据库
编程语言
Docker
Linux 开发工具
```

但它仍然运行在 Windows 上，所以一些：

```text
硬件
网络
Kernel
启动流程
底层系统管理
```

行为和真正独立安装的 Linux 服务器可能存在区别。

---

## 项目到底放 C 盘还是 WSL？

如果主要用：

```text
Linux CLI
Git
Node.js
Python
Docker
Go
Rust
```

推荐：

```bash
~/projects
```

即：

```text
Linux 文件系统
```

而不是：

```text
/mnt/c/...
```

---

## Windows 能访问 Linux 文件吗？

可以。

Explorer：

```text
\\wsl$
```

或者 WSL 中：

```bash
explorer.exe .
```

---

## WSL 中能运行 Windows 程序吗？

可以。

例如：

```bash
notepad.exe
```

```bash
explorer.exe .
```

---

## PowerShell 能运行 Linux 命令吗？

可以通过：

```powershell
wsl <command>
```

例如：

```powershell
wsl ls -la
```

# 总结

WSL 2 的核心结构：

```text
Windows
   │
   ▼
WSL 2
   │
   ▼
Lightweight Utility VM
   │
   ▼
Linux Kernel
   │
   ▼
Linux Distribution
   │
   ▼
Ubuntu
   │
   ├── Bash
   ├── apt
   ├── systemd
   ├── Git
   └── Development Tools
```

使用 WSL 2 时要先建立几个核心观念：

```text
WSL 2 ≠ Ubuntu

Windows ≠ Linux

PowerShell ≠ Bash

Windows User ≠ Linux User

/home ≠ /mnt/c

wsl --update ≠ apt update
```

开发环境推荐：

```text
Windows
│
├── VS Code
├── Browser
├── Docker Desktop
│
└── WSL 2
    │
    └── Ubuntu
        │
        ├── ~/projects
        ├── Git
        ├── Python
        ├── Node.js
        └── Linux CLI
```

最终目标不是：

> “在 Windows 里会打开一个 Ubuntu Terminal。”

而是理解：

> **Windows 负责桌面和宿主环境，WSL 2 提供完整的 Linux 开发环境，两者可以互相调用并组成一套高效的开发工作站。**
