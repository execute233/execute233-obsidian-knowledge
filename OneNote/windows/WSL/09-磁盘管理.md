# WSL2 磁盘管理

> [!abstract]
> 每个 WSL 2 Distribution 都使用一个虚拟硬盘保存 Linux 文件系统，通常表现为 `ext4.vhdx`。
>
> 最重要的概念：
>
> **Linux 看到的文件系统容量、VHDX 的最大虚拟容量、Windows 实际占用空间，是三个不同概念。**

Microsoft 当前文档说明，每个 WSL 2 Distribution 使用 `ext4` 文件系统的 VHDX，并按需要动态增长；当前默认最大虚拟容量为 `1TB`。

---

# 1. WSL 2 的磁盘结构

假设安装了 Ubuntu：

```text
Windows Disk
│
└── ext4.vhdx
    │
    └── ext4
        ├── /
        ├── /home
        ├── /etc
        ├── /usr
        └── /var
```

Linux 中看到：

`/`

Windows 实际保存的是：

`ext4.vhdx`

所以：

`~/projects`

最终也是存在这个 VHDX 中，而不是一个普通的 Windows 文件夹。

---

# 2. VHDX 是动态增长的

WSL 2 使用的虚拟磁盘会根据数据增长。

例如：

```text
虚拟最大容量：1 TB
Windows 实际占用：30 GB
Linux 已使用：25 GB
```

这完全正常。

`1TB` 并不意味着 Windows C 盘立即被占用 `1TB`。

它只是：

`VHDX Maximum Virtual Size`

而实际文件大小会随着 Linux 数据增加而扩大。

---

# 3. 三个容量概念

需要明确区分：

## Linux File System Size

Linux：

```bash
df -h /
```

例如：

```text
Filesystem      Size  Used Avail Use%
/dev/sdc       1007G   25G  931G   3%
```

这里的 `Size` 是 Linux 文件系统可以使用的虚拟容量。

---

## VHDX Virtual Size

例如：

`1TB`

表示 VHDX 最大允许扩展到多大。

---

## Physical Size

Windows Explorer 中：

`ext4.vhdx → 30GB`

这才是当前真正占用 Windows 磁盘的大致大小。

因此：

```text
Virtual Size
≠
Used Space
≠
Physical VHDX Size
```

Microsoft 特别说明，Linux 可能看到完整的 `1TB` 最大容量，即使 Windows 主机本身根本没有 `1TB` 可用空间。

---

# 4. 查看 Linux 磁盘使用

最常用：

```bash
df -h /
```

查看所有文件系统：

```bash
df -h
```

查看文件系统类型：

```bash
df -hT
```

查看 Block Device：

```bash
lsblk
```

Microsoft 官方的 WSL 磁盘管理文档也使用 `df` 和 `lsblk` 来检查 VHD 与 Block Device。

---

# 5. 找出谁占用了空间

查看 Home：

```bash
du -xh --max-depth=1 ~ | sort -h
```

查看 `/var`：

```bash
sudo du -xh --max-depth=1 /var | sort -h
```

例如常见大户：

* `~/projects`
* `~/.cache`
* `~/.local`
* `/var/cache`
* `/var/lib`
* Docker / Container 数据
* Package Manager Cache
* 编译产物
* `node_modules`
* Python Virtual Environment

进一步：

```bash
du -sh ~/projects/*
```

---

# 6. Linux 删除文件 ≠ VHDX 马上变小

这是 WSL 2 最容易误解的地方之一。

假设：

```text
ext4.vhdx = 100 GB
```

然后 Linux 中删除：

`60GB`

Linux：

```bash
df -h /
```

会看到可用空间增加。

但是 Windows Explorer 中的：

`ext4.vhdx`

不一定马上从 `100GB` 变成 `40GB`。

原因是：

> Linux 文件系统已经把 Block 标记为空闲，但动态 VHDX 文件的物理大小并不等价于文件系统当前 Used Space。

Windows 本身提供 `compact vdisk` 来压缩动态扩展型 VHD 的物理大小，但 Microsoft 当前 WSL 磁盘管理指南主要推荐通过 WSL 自身机制管理 Distribution，而不是日常手动操作其内部 VHDX。

---

# 7. 不要直接操作 AppData 中的 WSL 文件

Microsoft 明确警告：

> 不要使用 Windows 工具直接修改、移动或编辑 WSL 在 `AppData` 中的内部文件。

否则可能导致 Distribution 损坏。

例如不要直接：

```text
找到 ext4.vhdx
→ 剪切
→ 粘贴到 D:
```

也不要直接修改：

```text
AppData\Local\Packages\...\LocalState
```

正常访问 Linux 文件使用：

`\\wsl$\Ubuntu`

或者：

```bash
explorer.exe .
```

---

# 8. 找到 Distribution 的 VHDX

Microsoft 提供了 PowerShell 查询方式。

例如寻找 Ubuntu：

```powershell
(Get-ChildItem -Path HKCU:\Software\Microsoft\Windows\CurrentVersion\Lxss |
Where-Object {
    $_.GetValue("DistributionName") -eq "Ubuntu"
}).GetValue("BasePath") + "\ext4.vhdx"
```

可能得到类似：

```text
C:\Users\<user>\AppData\Local\Packages\...\LocalState\ext4.vhdx
```

这个命令适合：

* 排查磁盘占用
* VHD Repair
* Backup
* 高级磁盘操作

但不要因为找到了路径就直接手工移动它。

---

# 9. 默认最大容量

当前 WSL 2 Distribution 默认 VHD 最大容量为：

`1TB`

旧版本 WSL 曾经使用：

`512GB`

甚至：

`256GB`

所以网上看到旧教程里的 `256GB / 512GB` 不一定适用于现代 WSL。

---

# 10. 扩容 WSL Distribution

现代 WSL 已经支持：

`wsl --manage`

Microsoft 当前要求：

`WSL 2.5+`

才能直接使用该命令调整磁盘容量。

先：

```powershell
wsl --version
```

如果需要：

```powershell
wsl --update
```

---

# 11. 使用 `wsl --manage --resize`

假设 Ubuntu 扩展到：

`2TB`

先关闭 WSL：

```powershell
wsl --shutdown
```

然后：

```powershell
wsl --manage Ubuntu --resize 2TB
```

支持单位：

`B / M / MB / G / GB / T / TB`

目前不支持：

`2.5TB`

这种小数形式。

---

# 12. 为什么现在不推荐优先使用 DiskPart 扩容？

旧教程通常需要：

```text
diskpart
→ select vdisk
→ expand vdisk
→ resize2fs
```

Microsoft 目前仍保留这套 Manual Expansion 方法，但现代 WSL `2.5+` 已经可以直接：

```powershell
wsl --manage Ubuntu --resize 2TB
```

因此新环境优先使用 `wsl --manage` 即可。

---

# 13. `.wslconfig` 的 `defaultVhdSize`

如果希望 **以后新创建的 Distribution** 使用不同的默认最大 VHD 容量，可以配置：

```ini
[wsl2]
defaultVhdSize=512GB
```

它影响新 Distribution 的默认 VHD 最大容量。

已经存在的 Distribution 要调整容量，优先使用：

`wsl --manage <Distro> --resize <Size>`

而不是只修改 `.wslconfig`。

---

# 14. `sparseVhd`

WSL 提供实验配置：

```ini
[experimental]
sparseVhd=true
```

当前 Microsoft 文档说明：

`sparseVhd=true`

会让**新创建的 VHD**自动配置为 Sparse VHD。

当前默认值：

`false`。

> [!warning]
> `sparseVhd` 当前仍位于 `[experimental]`。
>
> 不建议仅为了“省空间”就无脑开启。

---

# 15. 不要混淆 `autoMemoryReclaim`

另一个配置：

```ini
[experimental]
autoMemoryReclaim=dropCache
```

控制的是：

**RAM 回收**

不是：

**磁盘空间回收**

所以：

```text
autoMemoryReclaim
→ Memory

sparseVhd
→ VHD 行为
```

这是两个完全不同的功能。Microsoft 当前文档把两者都列在 WSL 实验配置中。

---

# 16. Distribution 放到其他磁盘

如果新安装 Distribution，现代 `wsl --install` 支持：

`--location`

用于指定安装目录。

例如可以根据当前 `wsl --help` 支持情况，将新的 Distribution 安装到其他磁盘，而不是全部放在系统盘。

已经存在的 Distribution，则更常使用：

`export → import`

进行迁移。

详细放到：

[[WSL2备份与迁移]]

---

# 17. `wsl --export`

WSL 可以导出 Distribution：

```powershell
wsl --export Ubuntu D:\Backup\ubuntu.tar
```

默认导出格式是：

`tar`

WSL 2 也支持：

```powershell
wsl --export Ubuntu D:\Backup\ubuntu.vhdx --vhd
```

导出为 VHDX。

---

# 18. `wsl --import`

例如：

```powershell
wsl --import UbuntuDev D:\WSL\UbuntuDev D:\Backup\ubuntu.tar --version 2
```

结构：

```text
Distribution Name
        ↓
UbuntuDev

Install Location
        ↓
D:\WSL\UbuntuDev

Backup
        ↓
ubuntu.tar
```

`wsl --import` 可以因此用于：

* Backup Restore
* 创建副本
* Distribution Migration
* 把 Distribution 放到其他磁盘

Microsoft 当前 WSL CLI 正式支持 `--export`、`--import` 和 WSL 2 的 `--vhd`。

---

# 19. `wsl --import-in-place`

WSL 2 还支持：

```powershell
wsl --import-in-place UbuntuDev D:\WSL\Ubuntu\ext4.vhdx
```

前提是：

VHDX 使用 `ext4` 文件系统。

这个功能更偏高级场景，例如：

* 已经存在 VHDX
* 恢复 Distribution
* 高级迁移

普通 Backup 更容易使用：

`export / import`

---

# 20. `wsl --unregister` 非常危险

```powershell
wsl --unregister Ubuntu
```

会永久删除该 Distribution 的：

* 文件
* Package
* Linux 配置
* 用户数据

Microsoft 明确警告，这个操作完成后相关数据会永久丢失。

因此迁移通常应该：

```text
export
↓
验证 Backup
↓
import
↓
验证新 Distribution
↓
最后才 unregister 原 Distribution
```

---

# 21. Docker Desktop 有自己的磁盘

这一点和 WSL Ubuntu 必须分开。

Ubuntu：

```text
Ubuntu
└── ext4.vhdx
```

Docker Desktop：

```text
Docker Desktop
└── docker_data.vhdx
```

所以：

`Ubuntu 磁盘占用`

和：

`Docker Images / Volumes 占用`

不是同一个问题。

Docker 官方当前说明，WSL 2 Engine 的数据默认位于：

`%LOCALAPPDATA%\Docker\wsl`

并支持通过 Docker Desktop 设置修改数据位置。

---

# 22. Docker 的 `docker_data.vhdx`

Docker Desktop 官方 Backup 文档当前给出的 Windows 数据文件是：

`%LOCALAPPDATA%\Docker\wsl\data\docker_data.vhdx`

其中可能包含：

* Images
* Container Layers
* Build Cache
* Docker-managed Data

Docker Desktop 无法启动而需要恢复时，官方文档也将这个 VHDX 作为整体数据备份对象。

---

# 23. 查看 Docker 磁盘占用

不要先去看 VHDX。

先：

```bash
docker system df
```

它会告诉你：

* Images
* Containers
* Local Volumes
* Build Cache

这样才能知道 Docker 的空间到底花在哪里。

---

# 24. Docker Build Cache

开发过程中非常容易增长的是：

`Build Cache`

例如频繁：

```bash
docker build .
```

或者：

```bash
docker compose build
```

会不断产生 Build Cache。

如果确认不需要：

```bash
docker builder prune
```

更加激进：

```bash
docker builder prune -a
```

删除前应该先确认是否接受下一次 Build 失去缓存。

Docker 官方把 Build Cache 列为可 Prune 的 Docker Object。

---

# 25. `docker system prune`

可以清理多个未使用资源：

```bash
docker system prune
```

默认会清理：

* Stopped Containers
* 未使用 Network
* Dangling Images
* Unused Build Cache

Docker 官方明确说明，Volume 默认不会被 `docker system prune` 删除。

---

# 26. `docker system prune -a`

```bash
docker system prune -a
```

还会删除没有被 Container 使用的其他 Image。

这比普通：

`docker system prune`

激进很多。

不要为了清几 GB 空间就习惯性使用。

---

# 27. `--volumes` 要特别小心

例如：

```bash
docker system prune -a --volumes
```

会进一步涉及未使用 Volume。

Volume 中可能有：

* PostgreSQL
* MySQL
* Redis
* Elasticsearch
* 应用持久化数据

Docker 官方也因为数据风险，默认不会在 `docker system prune` 中删除 Volume。

> [!danger]
> 不确定 Volume 中是什么数据时，不要使用 `--volumes`。

---

# 28. 推荐 Docker 清理顺序

先看：

```bash
docker system df
```

再针对性处理。

例如 Build Cache 很大：

```bash
docker builder prune
```

旧 Image 很多：

```bash
docker image prune
```

Stopped Container 很多：

```bash
docker container prune
```

Network：

```bash
docker network prune
```

不要一上来：

```bash
docker system prune -a --volumes
```

Docker 官方也提供针对各类 Docker Object 的独立 Prune 命令。

---

# 29. Docker Data 移到其他磁盘

Docker Desktop 当前允许修改 WSL 2 Engine 数据位置。

默认：

`C:\Users\<user>\AppData\Local\Docker\wsl`

需要迁移时优先使用：

`Docker Desktop → Settings → Resources`

中的数据位置配置，而不是手动移动内部 VHDX。

---

# 30. WSL 磁盘满了怎么排查？

推荐：

## 1. 查看 Windows 剩余空间

先确认宿主机磁盘本身是否已经满。

## 2. 查看 Linux

```bash
df -h /
```

## 3. 查看大目录

```bash
du -xh --max-depth=1 ~ | sort -h
```

以及：

```bash
sudo du -xh --max-depth=1 /var | sort -h
```

## 4. 查看 Docker

```bash
docker system df
```

## 5. 判断是哪一个 VHDX

区分：

`Ubuntu ext4.vhdx`

与：

`Docker docker_data.vhdx`

## 6. 如果真的到达 VHD 最大容量

使用：

```powershell
wsl --manage Ubuntu --resize 2TB
```

当前 Microsoft 推荐现代 WSL 使用 `wsl --manage --resize` 扩容 Distribution VHD。

---

# 31. 磁盘损坏 / Read Only

如果 WSL 启动出现类似：

`mounted read-only as a fallback`

可能说明 Distribution VHD 出现文件系统问题。

Microsoft 官方流程包括：

`wsl --shutdown`

然后使用：

`wsl --mount <VHDX> --vhd --bare`

再通过 `e2fsck` 修复 ext4 文件系统。

> [!warning]
> 这是 Repair 操作。
>
> 不要在没有 Backup、没有确认 Block Device 的情况下随便执行 `e2fsck`。

---

# 32. 为什么突然断电可能影响 VHD？

WSL 2 Distribution 本质上仍然是：

`ext4 filesystem inside VHDX`

如果 Windows：

* 强制关机
* 蓝屏
* 突然断电
* 强制结束存储操作

文件系统可能像真实 Linux 磁盘一样出现一致性问题。

Microsoft 当前 WSL Repair 文档也明确把突然关机或断电列为可能导致 VHD Mount Error 的原因之一。

---

# 33. 不要把 WSL 当唯一数据备份

你的：

`~/projects`

如果已经进入 Git：

真正重要的 Source Code 应该 Push 到远端。

其他 Linux 配置：

* `~/.ssh`
* `~/.config`
* 数据库
* Local Dataset
* 自定义环境

则应该单独设计 Backup。

WSL 的 `ext4.vhdx` 是运行环境，不应该成为唯一数据副本。

---

# 34. 推荐磁盘布局

如果系统盘空间有限，可以考虑：

```text
C:
├── Windows
├── VS Code
└── Applications

D:
├── WSL/
│   ├── Ubuntu/
│   └── Backup/
│
└── Docker/
```

具体迁移应该使用：

* WSL `export / import`
* `wsl --install --location`
* Docker Desktop Data Location

而不是手动移动内部 VHDX。WSL 当前 CLI 支持安装位置、导入位置以及 VHD Import；Docker Desktop 也支持修改 WSL Data Location。

---

# 35. 核心心智模型

```text
Windows Physical Disk
│
├── WSL Ubuntu
│   │
│   └── ext4.vhdx
│       │
│       └── ext4
│           ├── ~/projects
│           ├── /usr
│           └── /var
│
└── Docker Desktop
    │
    └── docker_data.vhdx
        │
        ├── Images
        ├── Containers
        ├── Volumes
        └── Build Cache
```

所以：

```text
WSL 磁盘问题
≠
Docker 磁盘问题
```

排查时先确认到底是哪一个 VHDX 在增长。
