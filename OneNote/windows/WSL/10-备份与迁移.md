# WSL2 备份与迁移

> [!abstract]
> WSL 官方推荐使用 `wsl --export` / `wsl --import` 对 Distribution 进行备份和迁移。
>
> 核心流程：
>
> `export → verify → import → verify → unregister old distro`

---

# 1. 先区分需要备份什么

WSL 开发环境至少存在这些不同的数据层：

| 数据                  | 推荐备份方式                         |
| ------------------- | ------------------------------ |
| Git Repository      | Git Remote                     |
| Linux Distribution  | `wsl --export`                 |
| `~/.ssh`            | 独立加密备份                         |
| Dotfiles            | Private Git / Backup           |
| `.wslconfig`        | Windows 文件备份                   |
| Docker Image        | Registry / `docker image save` |
| Docker Volume       | Volume Backup                  |
| Docker Desktop 全部数据 | `docker_data.vhdx`             |

最重要的是：

**WSL Distribution Backup ≠ Docker Desktop Backup。**

Docker Desktop 使用独立的数据存储，因此导出 `Ubuntu` 不会顺便备份 Docker Desktop 的 Images / Volumes。

---

# 2. 查看当前 Distribution

PowerShell：

```powershell
wsl -l -v
```

例如：

```text
NAME      STATE     VERSION
Ubuntu    Running   2
```

后面的命令都需要使用正确的 Distribution Name，例如 `Ubuntu`。

---

# 3. TAR 备份

`wsl --export` 默认导出为 tar。

为了减少数据库、日志等正在写入造成的不一致，备份前建议先停止 Distribution：

```powershell
wsl --terminate Ubuntu
```

然后：

```powershell
wsl --export Ubuntu D:\WSL-Backup\Ubuntu.tar
```

建议备份文件带日期：

```powershell
wsl --export Ubuntu D:\WSL-Backup\Ubuntu-YYYY-MM-DD.tar
```

确认：

```powershell
Get-Item D:\WSL-Backup\Ubuntu-YYYY-MM-DD.tar
```

还可以生成 Hash：

```powershell
Get-FileHash D:\WSL-Backup\Ubuntu-YYYY-MM-DD.tar -Algorithm SHA256
```

---

# 4. TAR 恢复

准备安装位置：

```powershell
New-Item -ItemType Directory -Path D:\WSL\Ubuntu-Restore
```

然后：

```powershell
wsl --import Ubuntu-Restore `
  D:\WSL\Ubuntu-Restore `
  D:\WSL-Backup\Ubuntu.tar `
  --version 2
```

结构：

`Ubuntu-Restore` 是新的 Distribution Name。

`D:\WSL\Ubuntu-Restore` 是实际安装位置。

`Ubuntu.tar` 是 Backup。

Microsoft 当前 `wsl --import` 支持指定 Distribution Name、Install Location 和 WSL Version。

检查：

```powershell
wsl -l -v
```

进入：

```powershell
wsl -d Ubuntu-Restore
```

---

# 5. VHDX Backup

WSL 2 还可以直接导出 VHDX：

```powershell
wsl --export Ubuntu D:\WSL-Backup\Ubuntu.vhdx --vhd
```

当前 Microsoft 基础命令文档支持 WSL 2 使用 `--vhd` 导出和导入 VHDX。

可以理解：

`tar` 更偏向 Distribution Archive。

`vhdx` 更偏向完整 ext4 Virtual Disk。

如果只是常规 Backup / Clone，tar 已经很好用。

如果是整个 Distribution 的磁盘级迁移，VHDX 很方便。

---

# 6. 导入 VHDX

可以：

```powershell
wsl --import Ubuntu-Restore `
  D:\WSL\Ubuntu-Restore `
  D:\WSL-Backup\Ubuntu.vhdx `
  --vhd
```

WSL 2 才支持这种 VHD 导入方式。

---

# 7. `--import-in-place`

如果已经有一个 ext4 VHDX，可以直接注册：

```powershell
wsl --import-in-place UbuntuDev D:\WSL\UbuntuDev\ext4.vhdx
```

要求这个 VHDX 使用：

`ext4`

Microsoft 当前正式支持 `wsl --import-in-place`。

它与普通 `--import` 最大的区别是：

```text
--import
Backup File
   ↓
创建 / 导入 Distribution

--import-in-place
已有 ext4.vhdx
   ↓
直接注册为 Distribution
```

---

# 8. 把 Ubuntu 迁移到 D 盘

这是最实用的场景之一。

Microsoft 当前 FAQ 推荐的方式就是：

`export VHD → unregister → import-in-place`。

## Step 1：停止

```powershell
wsl --terminate Ubuntu
```

## Step 2：导出到 D 盘

```powershell
New-Item -ItemType Directory -Path D:\WSL\Ubuntu
```

```powershell
wsl --export Ubuntu D:\WSL\Ubuntu\ext4.vhdx --vhd
```

## Step 3：确认备份存在

```powershell
Get-Item D:\WSL\Ubuntu\ext4.vhdx
```

建议此时再复制一份真正的 Backup：

```powershell
Copy-Item `
  D:\WSL\Ubuntu\ext4.vhdx `
  D:\WSL-Backup\Ubuntu-before-migration.vhdx
```

---

# 9. `wsl --unregister` 是危险操作

确认 Backup 正常后才执行：

```powershell
wsl --unregister Ubuntu
```

> [!danger]
> `wsl --unregister` 会永久删除原 Distribution 的数据、软件和配置。
>
> Microsoft 官方明确将其标记为破坏性操作。

所以迁移顺序永远应该是：

```text
Export
  ↓
检查文件
  ↓
最好再做一份 Backup
  ↓
Unregister
```

绝对不要反过来。

---

# 10. 在 D 盘重新注册

```powershell
wsl --import-in-place Ubuntu D:\WSL\Ubuntu\ext4.vhdx
```

检查：

```powershell
wsl -l -v
```

启动：

```powershell
wsl -d Ubuntu
```

确认项目：

```bash
ls ~/projects
```

确认：

```bash
git --version
systemctl status
```

确认开发环境正常以后，迁移才算完成。Microsoft FAQ 当前给出的跨磁盘迁移方案也是这种 VHD Export + Import-in-place 流程。

---

# 11. Clone 一个 WSL 环境

有时候需要：

```text
Ubuntu
↓
Ubuntu-Lab
```

例如测试系统配置、升级 Package、做实验环境。

先：

```powershell
wsl --export Ubuntu D:\WSL-Backup\Ubuntu.tar
```

然后：

```powershell
wsl --import Ubuntu-Lab `
  D:\WSL\Ubuntu-Lab `
  D:\WSL-Backup\Ubuntu.tar `
  --version 2
```

现在：

```powershell
wsl -l -v
```

可能看到：

```text
Ubuntu
Ubuntu-Lab
```

两者之后是独立的 Distribution。

---

# 12. Imported Distribution 的 Default User

一个容易踩坑的地方是：

`wsl --import`

得到的 Distribution 没有 Store Distribution 的 Launcher。

因此：

```powershell
ubuntu config --default-user ema
```

这种 Launcher 命令不能用于 Imported Distribution。Microsoft 当前文档明确指出 Imported Distribution 应通过 `/etc/wsl.conf` 设置默认用户。

配置：

```ini
[user]
default=ema
```

位置：

`/etc/wsl.conf`

然后：

```powershell
wsl --terminate Ubuntu-Lab
wsl -d Ubuntu-Lab
```

检查：

```bash
whoami
```

---

# 13. `.wslconfig` 不在 Distribution 里面

这是 Backup 时非常重要的一点。

`.wslconfig` 位于：

`%UserProfile%\.wslconfig`

而：

`/etc/wsl.conf`

位于 Linux Distribution 内部。

因此：

```text
wsl --export
```

可以包含 Linux 中的：

`/etc/wsl.conf`

但不会包含 Windows Home 中的：

`.wslconfig`

所以 `.wslconfig` 应单独备份，例如：

```powershell
Copy-Item `
  "$env:USERPROFILE\.wslconfig" `
  "D:\WSL-Backup\.wslconfig"
```

---

# 14. SSH / Git / Dotfiles

完整 Distribution Export 通常会包含 Linux Home 中的数据，例如：

`~/.gitconfig`

`~/.ssh`

`~/.config`

但不应该因此就忽略独立 Backup。

推荐：

```text
Source Code
→ Git Remote

Dotfiles
→ Private Repository

SSH Private Keys
→ Encrypted Backup

WSL Distribution
→ export
```

尤其 `~/.ssh` 包含 Private Key，不要上传到公开 Git Repository。

---

# 15. 数据库 Backup 不应该只依赖 WSL Snapshot

例如 WSL 中运行：

* PostgreSQL
* MySQL
* Redis
* Elasticsearch

更稳妥的是同时保留应用级 Backup。

例如 PostgreSQL：

`pg_dump`

MySQL：

`mysqldump`

WSL Distribution Export 更适合作为：

**Environment Backup**

而数据库自己的 Backup 才是：

**Application Data Backup**

两层结合更加可靠。

---

# 16. Docker Desktop 必须单独备份

如果使用：

[[WSL2与Docker]]

中的 Docker Desktop WSL 2 Backend：

```text
Ubuntu
└── ext4.vhdx

Docker Desktop
└── docker_data.vhdx
```

这是两个独立的数据环境。

所以：

```powershell
wsl --export Ubuntu ...
```

不会备份：

* Docker Images
* Docker Build Cache
* Docker Named Volumes
* Docker Desktop Backend

Docker 官方明确要求 Docker Desktop 数据单独备份。

---

# 17. Docker Image Backup

如果 Docker Desktop 可以正常运行，更推荐：

```text
Dockerfile
+
compose.yaml
+
Registry
```

而不是把 Container 当成重要资产。

自己构建但还没 Push 的 Image 可以：

```bash
docker image save -o images.tar my-image:latest
```

恢复：

```bash
docker image load -i images.tar
```

Docker 官方当前 Backup 文档支持 `docker image save` / `docker image load` 作为本地 Image Backup 方式。

---

# 18. Docker Volume Backup

Volume 数据需要独立处理。

例如：

```bash
docker volume ls
```

Docker 官方提供：

* Docker Desktop Volume Export / Import
* 通过临时 Container + `tar` 备份 Volume

两种方式。

对于数据库 Volume，建议优先同时保留数据库自己的逻辑 Backup。

---

# 19. Docker Desktop 无法启动时

Docker 官方提供了更底层的 Disaster Recovery 方法。

Windows 当前 Docker Desktop 数据文件：

`%LOCALAPPDATA%\Docker\wsl\data\docker_data.vhdx`

如果 Docker Desktop 已经无法启动，可以：

1. 完全停止 Docker Desktop。
2. 复制 `docker_data.vhdx` 到安全位置。
3. 重装 Docker Desktop。
4. 将 VHDX 恢复到对应位置。

这是 Docker 官方的故障恢复方案。

正常运行时，不需要把这种底层 VHDX Copy 当成日常 Backup 的首选方案。

---

# 20. Windows 重装后的恢复流程

假设已经备份：

```text
D:\Backup\
├── Ubuntu.tar
├── .wslconfig
└── Docker/
```

Windows 重装后：

## 安装 WSL

```powershell
wsl --install --no-distribution
```

更新：

```powershell
wsl --update
```

## 创建目标目录

```powershell
New-Item -ItemType Directory -Path D:\WSL\Ubuntu
```

## Restore

```powershell
wsl --import Ubuntu `
  D:\WSL\Ubuntu `
  D:\Backup\Ubuntu.tar `
  --version 2
```

## 恢复 `.wslconfig`

```powershell
Copy-Item `
  D:\Backup\.wslconfig `
  "$env:USERPROFILE\.wslconfig"
```

然后：

```powershell
wsl --shutdown
```

---

先：

```powershell
wsl -l -v
```

进入：

```powershell
wsl -d Ubuntu
```

检查用户：

```bash
whoami
```

检查 Home：

```bash
ls ~
```

Git：

```bash
git config --list
```

SSH：

```bash
ls -la ~/.ssh
```

systemd：

```bash
systemctl status
```

项目：

```bash
ls ~/projects
```

如果使用 Docker Desktop，再重新安装 Docker Desktop、开启 WSL Integration，并单独恢复 Docker 数据。

# 22. 推荐 Backup Strategy

对于开发机，仆更推荐分层：

```text
Level 1
Source Code
→ Git Remote

Level 2
Dotfiles / SSH / Secrets
→ 独立安全 Backup

Level 3
WSL Distribution
→ wsl --export

Level 4
Database / Docker Volume
→ Application-level Backup

Level 5
Docker Desktop
→ Registry / Volume Backup / Disaster Recovery VHDX
```

这样不会把所有数据安全都压在一个：

`Ubuntu.tar`

上。

---

# 23. 推荐 Backup 命名

例如：

```text
WSL-Backup/
├── Ubuntu/
│   ├── Ubuntu-2026-08-01.tar
│   ├── Ubuntu-2026-08-08.tar
│   └── Ubuntu-2026-08-15.tar
│
├── config/
│   └── .wslconfig
│
└── docker/
```

不要长期只保留：

`Ubuntu-latest.tar`

否则新的损坏 Backup 可能覆盖最后一个正常版本。

---

# 24. 备份是否真的可用？

只有：

`export 成功`

还不能证明 Backup 一定可恢复。

比较可靠的验证方式是定期实际：

```powershell
wsl --import Ubuntu-Test `
  D:\WSL\Test `
  D:\WSL-Backup\Ubuntu.tar `
  --version 2
```

然后：

```powershell
wsl -d Ubuntu-Test
```

检查关键数据。

确认以后删除测试环境：

```powershell
wsl --unregister Ubuntu-Test
```

这里的 `unregister` 只针对你明确创建的测试 Distribution。

---

# 25. 推荐迁移流程

如果目标是：

`把 Ubuntu 从 C: 移到 D:`

推荐：

```text
1. wsl --terminate Ubuntu
       ↓
2. export
       ↓
3. 验证 Backup
       ↓
4. 再复制一份 Backup
       ↓
5. unregister 原 Ubuntu
       ↓
6. import / import-in-place 到 D:
       ↓
7. 检查 Default User
       ↓
8. 检查项目 / Git / SSH / systemd
       ↓
9. 确认环境完整
```

Microsoft 当前 FAQ 推荐使用 Export / Import 完成 WSL Distribution 的 Backup 和跨磁盘迁移。

# 26. 常用命令速查

查看：

```powershell
wsl -l -v
```

停止：

```powershell
wsl --terminate Ubuntu
```

TAR Export：

```powershell
wsl --export Ubuntu Ubuntu.tar
```

VHD Export：

```powershell
wsl --export Ubuntu Ubuntu.vhdx --vhd
```

TAR Import：

```powershell
wsl --import UbuntuDev D:\WSL\UbuntuDev Ubuntu.tar --version 2
```

VHD Import：

```powershell
wsl --import UbuntuDev D:\WSL\UbuntuDev Ubuntu.vhdx --vhd
```

In-place：

```powershell
wsl --import-in-place UbuntuDev D:\WSL\UbuntuDev\ext4.vhdx
```

删除 Distribution：

```powershell
wsl --unregister UbuntuDev
```

> [!danger]
> 最后一条会删除 Distribution，请确认名称和 Backup。
