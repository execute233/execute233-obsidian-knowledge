# WSL2 网络

> [!abstract]
> WSL 2 默认使用 `NAT` 网络。
>
> Windows 访问 WSL 服务通常可以直接使用 `localhost`；而在默认 NAT 模式下，WSL 访问 Windows 服务通常需要 Windows Host IP。
>
> Windows 11 22H2+ 可以使用 `mirrored networking`，让 Windows 与 WSL 的网络互操作更加直接。

---

# 1. WSL 2 默认网络模型

默认情况下，WSL 2 使用 `NAT`。

可以粗略理解：

```text
                LAN / Internet
                      │
                      ▼
               ┌─────────────┐
               │   Windows   │
               │  Host NIC   │
               └──────┬──────┘
                      │
                     NAT
                      │
               ┌──────▼──────┐
               │    WSL 2    │
               │ Virtual NIC │
               └─────────────┘
```

因此 Windows 与 WSL 2 在 NAT 模式下通常拥有不同的 IP。

---

# 2. 查看 WSL IP

在 PowerShell：

```powershell
wsl hostname -I
```

也可以指定 Distribution：

```powershell
wsl -d Ubuntu hostname -I
```

输出可能类似：

```text
172.30.98.229
```

注意是大写 `-I`。

`hostname -i` 与 `hostname -I` 的含义不同；获取 WSL 网络地址时应该使用 `hostname -I`。

---

# 3. 查看 Windows Host IP

在 WSL 中：

```bash
ip route show | grep -i default
```

可能看到：

```text
default via 172.30.96.1 dev eth0
```

其中 `172.30.96.1` 通常就是 NAT 模式下 WSL 所看到的 Windows Host 地址。

直接获取：

```bash
ip route show | grep -i default | awk '{ print $3 }'
```

---

# 4. Windows → WSL

这是日常开发最常见的方向。

假设在 WSL 中启动：

```bash
python3 -m http.server 8000
```

Windows 浏览器通常可以直接访问：

`http://localhost:8000`

也就是说：

```text
Windows Browser
      │
      │ localhost:8000
      ▼
WSL 2 :8000
```

WSL 2 默认开启 `localhostForwarding`，因此 Linux 中监听的端口可以从 Windows 的 `localhost:<port>` 访问。

---
# 6. WSL → Windows

假设 Windows 上运行：

```text
localhost:3000
```

在默认 NAT 模式下，WSL 通常不能简单使用：

```bash
curl http://localhost:3000
```

因为此时 WSL 的 `localhost` 指向 WSL 自己。

应该先找到 Windows Host IP：

```bash
HOST_IP=$(ip route show | grep -i default | awk '{ print $3 }')
```

然后：

```bash
curl "http://$HOST_IP:3000"
```

例如：

```text
WSL 2
  │
  │ 172.30.96.1:3000
  ▼
Windows
```

---

# 7. Windows 服务的监听地址

这里还有一个容易踩坑的地方。

假设 Windows 上的开发服务器只监听：

`127.0.0.1:3000`

那么从 WSL 使用 Windows Host IP：

`172.x.x.x:3000`

可能无法连接。

原因是程序只接受 loopback 流量。

如果确实需要通过 Host IP 访问，需要让服务监听：

`0.0.0.0`

或对应的 Windows 网络接口地址。

例如很多开发服务器都有：

```text
--host 0.0.0.0
```

之类的配置。

> [!warning]
> `0.0.0.0` 表示监听所有 IPv4 Interface，可能导致服务能够被局域网中的其他设备访问。
>
> 开发服务器、数据库、调试接口不要无脑绑定 `0.0.0.0`。

Microsoft 也特别提醒，通过远程 IP 连接会被视为 LAN 连接，因此应用必须允许 LAN 访问。

---

# 9. Mirrored Networking

Windows 11 22H2+ 支持 `mirrored networking`。

它会把 Windows 的网络接口镜像进 WSL，改善 Windows 与 WSL 的网络互操作。Microsoft 当前也建议优先尝试 mirrored networking。

主要能力包括：

* Windows ↔ WSL 可以通过 `127.0.0.1` 互相访问服务
* IPv6 支持
* 更好的 VPN 兼容性
* Multicast 支持
* 更直接的 LAN 访问

---

# 10. 开启 Mirrored Networking

配置文件：

`%UserProfile%\.wslconfig`

例如：

```ini
[wsl2]
networkingMode=mirrored
```

修改完成后：

```powershell
wsl --shutdown
```

重新进入：

```powershell
wsl
```

---

# 11. Mirrored 模式下的 localhost

启用 mirrored networking 后：

```text
Windows
   │
 localhost
   │
   ▼
WSL
```

以及：

```text
WSL
   │
 localhost
   │
   ▼
Windows
```

都可以工作。

例如 Windows 中：

```text
localhost:8000
```

访问 WSL Web Server。

WSL 中：

```bash
curl http://127.0.0.1:3000
```

访问 Windows Web Server。

目前这里主要指 IPv4 `127.0.0.1`；Microsoft 文档明确指出 mirrored 模式下此场景不支持 IPv6 loopback `::1`。

---

# 12. NAT 与 Mirrored 对比

| 能力                      | NAT            | Mirrored |
| ----------------------- | -------------- | -------- |
| Windows → WSL localhost | ✅              | ✅        |
| WSL → Windows localhost | ❌ 通常需要 Host IP | ✅        |
| IPv6                    | 较有限            | ✅        |
| VPN 兼容性                 | 可能出现问题         | 通常更好     |
| Multicast               | 有限制            | ✅        |
| LAN → WSL               | 需要额外配置         | 更直接      |
| Windows 11 22H2+        | 不要求            | 要求       |

---

# 13. 推荐使用哪个？

如果使用 Windows 11 22H2+，开发环境可以优先考虑：

```ini
[wsl2]
networkingMode=mirrored
```

特别是存在：

* VPN
* 公司代理
* WSL → Windows 本地服务
* IPv6
* LAN 调试

这些需求时。

但 mirrored networking 并不是“开启就绝对没有问题”，VPN、安全软件、Docker Desktop 等组件仍可能产生兼容性问题。Microsoft 的 WSL Troubleshooting 目前也记录了一些 mirrored networking 的已知问题。

---

# 14. DNS

WSL 中查看 DNS：

```bash
cat /etc/resolv.conf
```

通常可以看到：

```text
nameserver ...
```

默认情况下，`/etc/resolv.conf` 由 WSL 自动生成。

相关配置位于：

`/etc/wsl.conf`

例如：

```ini
[network]
generateResolvConf=true
```

默认值就是 `true`。

---

# 15. DNS Tunneling

现代 Windows 11 22H2+ 的 WSL 支持 `dnsTunneling`，并默认开启。

它不会简单地让 Linux DNS 请求作为普通网络数据包发送给 Windows DNS Server，而是通过 WSL 的虚拟化通道让 Windows 完成 DNS Resolution。

主要目的之一是改善：

* VPN
* 企业 DNS
* 复杂网络配置

下的 DNS 兼容性。

---
# 17. DNS 排错

如果出现：

```bash
curl https://example.com
```

失败，可以先分辨：

### IP 是否通

```bash
ping 1.1.1.1
```

### DNS 是否正常

```bash
getent hosts example.com
```

或者：

```bash
nslookup example.com
```

如果：

```text
IP 能访问
域名不能访问
```

通常优先检查 DNS。

还可以查看：

```bash
cat /etc/resolv.conf
```

不要遇到 DNS 问题就直接永久覆盖 `/etc/resolv.conf`。

WSL 默认会自动生成它，而且现代 WSL 还有 `dnsTunneling`。手动固定 DNS 可能反而破坏 VPN 或公司内部域名解析。

---

# 18. Auto Proxy

WSL 还可以同步 Windows 的 HTTP Proxy 配置。

`.wslconfig`：

```ini
[wsl2]
autoProxy=true
```

当前默认值为 `true`。

适用于 Windows 本身已经配置：

* HTTP Proxy
* HTTPS Proxy
* 企业 Proxy

的环境。

---

# 19. 查看 Proxy

在 WSL：

```bash
env | grep -i proxy
```

可能看到：

```text
HTTP_PROXY=...
HTTPS_PROXY=...
NO_PROXY=...
```

具体行为取决于 Windows 与 WSL 配置。

---

# 20. Firewall

WSL 网络并不是绕过 Windows Firewall 的独立网络。

在 Windows 11 22H2+ 且较新的 WSL 中，Hyper-V Firewall 默认参与 WSL 网络流量过滤。

所以遇到：

```text
服务已经监听
IP 正确
端口正确
但仍然无法连接
```

还需要检查：

* Windows Defender Firewall
* Hyper-V Firewall
* 企业安全策略
* 第三方安全软件

---

# 21. 查看服务是否真的监听

在 WSL：

```bash
ss -lntp
```

例如：

```text
LISTEN 0 4096 0.0.0.0:8000 ...
```

说明监听：

`0.0.0.0:8000`

如果：

```text
127.0.0.1:8000
```

说明只监听 WSL loopback。

对于 UDP：

```bash
ss -lnup
```


检查指定端口：

```powershell
Get-NetTCPConnection -LocalPort 8000
```

也可以：

```powershell
netstat -ano
```

# 25. LAN → WSL

假设手机、另一台电脑要访问 WSL 中：

`8000`

这和 Windows 本机访问 `localhost:8000` 是两个不同的问题。

---

## NAT 模式

默认 NAT 模式下，WSL 2 类似一台位于 Windows 后面的虚拟机。

LAN 设备不能默认直接访问 WSL VM。

一种方案是在 Windows 做 Port Proxy：

```powershell
netsh interface portproxy add v4tov4 `
  listenport=8000 `
  listenaddress=0.0.0.0 `
  connectport=8000 `
  connectaddress=<WSL_IP>
```

WSL IP：

```powershell
wsl hostname -I
```

同时还需要考虑 Windows Firewall。

---

# 26. NAT Port Proxy 的问题

WSL 2 NAT IP 可能变化。

因此这种配置：

```text
Windows:8000
    ↓
172.x.x.x:8000
```

中的目标 IP 不一定永久稳定。

这也是 mirrored networking 在开发场景下更方便的原因之一。

---

# 27. Mirrored 模式下 LAN 访问

Mirrored networking 支持直接从 LAN 访问 WSL。

但：

* Linux 服务需要监听正确 Interface
* Hyper-V Firewall 需要允许流量
* Windows Firewall / 网络策略可能仍然生效

Microsoft 官方文档明确要求根据场景配置 Hyper-V Firewall inbound rule。

所以：

> `networkingMode=mirrored` 不等于自动把所有 WSL 端口暴露给 LAN。

---
# 29. `.wslconfig` 网络配置

常见配置：

```ini
[wsl2]
networkingMode=mirrored
dnsTunneling=true
autoProxy=true
firewall=true
```

其中：

| 配置                    |    默认值 | 作用                                   |
| --------------------- | -----: | ------------------------------------ |
| `networkingMode`      |  `NAT` | WSL 网络模式                             |
| `dnsTunneling`        | `true` | DNS 请求通过 WSL 虚拟化通道处理                 |
| `autoProxy`           | `true` | 使用 Windows HTTP Proxy                |
| `firewall`            | `true` | Windows / Hyper-V Firewall 过滤 WSL 流量 |
| `localhostForwarding` | `true` | NAT 模式下 Windows localhost 转发到 WSL    |

`networkingMode=mirrored` 时，`localhostForwarding` 配置会被忽略。

---

# 31. VPN

VPN 是 WSL 2 网络最常见的问题来源之一。

NAT 模式下：

```text
WSL
 ↓
NAT
 ↓
Windows
 ↓
VPN
```

企业 VPN 可能修改：

* Route
* DNS
* Firewall
* Proxy

从而导致 WSL：

* 无法联网
* DNS 失败
* 内网域名无法解析
* 内网 IP 无法访问

Microsoft 当前推荐的方向通常是：

* `mirrored networking`
* `dnsTunneling=true`

因为两者就是为了改善此类复杂网络环境兼容性。


# 35. WSL 网络与 Docker Network

这里先只建立边界。

WSL 网络：

```text
Windows
   ↕
WSL 2
```

Docker Network：

```text
WSL / Docker Engine
       │
       ├── Container A
       └── Container B
```

两者不是一回事。

例如：

```yaml
services:
  api:
    ports:
      - "8000:8000"

  redis:
    image: redis
```

`api → redis`：

```text
redis:6379
```

属于 Docker Network。

Windows Browser：

```text
localhost:8000
```

访问 Docker Published Port，则又涉及 Docker Desktop / WSL / Windows 的网络转发。

这一部分放到：

`[[WSL2与Docker]]`

单独讲。

# 36. 核心心智模型

### 默认 NAT

```text
                  Internet
                     │
                     ▼
               Windows Host
               192.168.x.x
                     │
                    NAT
                     │
                     ▼
                  WSL 2
                172.x.x.x
```

Windows → WSL：

`localhost`

WSL → Windows：

`Windows Host IP`

---

### Mirrored

```text
            Windows Network Interfaces
                     │
             Mirrored into WSL
                     │
          ┌──────────┴──────────┐
          │                     │
       Windows                WSL 2
          │                     │
          └──── localhost ──────┘
```

适合现代 Windows 11 开发环境。
