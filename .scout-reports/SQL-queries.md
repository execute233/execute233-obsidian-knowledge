## 维度逐项扫描结果

### 1. 标题层级
- 全 17 篇: **零 H1 标题** —— 文件首行均为纯文本或有序列表项,无 `# 标题` 起始。
- 跳级 H1→H3: 无 (因为根本没有 H1)。
- 误判的 "伪 H1": 仅 `SQL语句/有用的SQL.md` 第 3、5 行 `# 可以这样写`、`# 比如这里就是筛选列中重复的元素` 被 markdown 解析器识别为 H1,而原意是 SQL 行内注释。

### 2. Frontmatter (YAML)
- 全 17 篇: **零 frontmatter** (`---` 块) —— 字段一致性不是问题,因为根本不存在。整批一致缺失。

### 3. 列表风格
- 无序列表: 全部使用 `- ` (一致);未发现 `* ` 或 `+ `。
- 有序列表: 全部手动编号 `1. 2. 3.`。
- **异常**: `SQL语句/DML数据操作.md` 第 1 行: `1. 插入数据 3. 修改数据` —— 两条列表项挤在一行,第 2 行直接是 `4. 删除数据`,编号 1→3→4,**缺失第 2 项**。
- 缩进嵌套: 无嵌套子列表,无问题。

### 4. 强调风格
- 加粗 `**xx**`: 0 处 (本批范围)。
- 下划线 `__xx__`: 0 处。
- 斜体 `*xx*` / `_xx_`: 0 处。
- 结论: 不存在强调风格混用 (本批范围完全无强调)。

### 5. 表格
- 仅 `MySQL/数据类型.md` 含 4 张 GFM 表 (第 8-15、24-28、33-40、42-52 行)。
- 全部使用 `|---|---|---|` 分隔符,风格一致。
- **轻微不一致**: 4 张表表头列名不统一 (第 1、2 张表头为 `数据类型|字节数|取值范围`;第 3 张为 `数据类型|取值范围|日期格式`;第 4 张为 `数据类型|类型说明`) —— 列数与语义均不同,属内容设计问题。

### 6. 链接
- 内部 `[[wikilink]]`: 0 处 (本批范围)。
- 外部 `[text](url)`: 0 处。
- 损坏链接: 0 处。
- 结论: 本批完全无链接,无问题。

### 7. HTML 残留
- `<details>`、`<br>`、`<summary>` 等块级 HTML: 0 处。
- 类 HTML 残留: `SQL语句/DQL数据查询.md` 第 3 行 `SELECT [ALL|DISTINCT] \<column\> [AS name] [{, \<column2\> [as name2]}]}` —— 角括号被反斜杠转义为 `\<...\>`。在 fenced code 内通常无需转义 (已清理项里"反斜杠转义"应排除代码块内),需人工判断语义 (刻意 or 残留)。

### 8. 图片
- `![[wikilink]]` wikilink 形式: 0 处 (本批范围,所有 `![[]]` 在 Redis/ 下,与本任务无关)。
- `![alt](path)` 形式: 0 处。
- 结论: 本批无图片。

### 9. 中文/英文标点混用
- 大量 SQL 例句内部使用英文标点 (`,` `.` `(` `)` `[` `]` `|` `;`),与中文叙述句 `,。、;:()` 混排;但全部位于 SQL 代码内,符合惯例。
- 全角 `（）` 与半角 `()` 混用: 仅出现在 SQL 标识符上下文 (`（Readuncommitted)` 等),不构成 markdown 格式问题。

### 10. 特殊残留
- `[TOC]` 占位符: 0 处。
- 任务列表 `[ ]`: 0 处 (第 26 行 `[] - 某个范围内的字符` 是 SQL 通配符说明,非 checkbox)。
- Emoji 乱码: 0 处。

## 偏离清单 (按严重程度排)

### 高优
1. **`SQL语句/DQL数据查询.md:1` 代码块语言标签错配** —— 开头 `\`\`\`xml` 实际包裹纯 SQL 语句 (`SELECT [ALL|DISTINCT] …`),渲染/语法高亮失效,首屏即出错。
2. **`SQL语句/有用的SQL.md:3,5` 误生成 H1 标题** —— `# 可以这样写`、`# 比如这里就是筛选列中重复的元素` 是 SQL 行内注释但被解析为 H1,与该文件结构意图冲突;同时文件首行 `1. 统计表中某列出现元素的数量` 是有序列表首项而非标题。
3. **`SQL语句/DML数据操作.md:1` 有序列表编号错乱** —— `1. 插入数据 3. 修改数据` 一行两项,接 `4. 删除数据`,**缺失 2**,且未换行,渲染时合并为同一项,语义丢失。

### 中优
4. **全 17 篇均无 H1 标题** —— 首行皆为纯文本/列表项,无 `# 文件名` 起首,文档大纲不可生成。
5. **全 17 篇均无 YAML frontmatter** —— 字段一致(因为都没有),但完全缺失元数据。
6. **`SQL语句/DQL数据查询.md:39-41` 空代码块** —— `\`\`\`sql\n去重查询\n\`\`\`` 仅 4 字标题被错误地作为代码块,造成视觉与语义割裂。
7. **SQL 例句呈现形态不统一** —— DQL 中 fenced code、行内裸 SQL、列表内嵌 SQL 混用;DDL/DML/DCL/MySQL 函数等全部以裸行书写,无 fenced code 围栏,可读性差且无法语法高亮。
8. **`MySQL/数据类型.md` 4 张表表头列名不一致** —— `字节数|取值范围` × 2、`取值范围|日期格式` × 1、`类型说明` × 1,语义与列数差异未在表标题中区分。

### 低优
9. **`SQL语句/DQL数据查询.md:3` 反斜杠转义角括号** —— `\<column\>`、`\<column2\>`,位于 `xml` 标签代码块内 (见 §7);若保持原代码块,该写法在 fenced code 中通常无需转义,但因块标签本身错配 (问题 1),整体应同步重写。
10. **(内容层,非格式)** 关键字拼写错误 (建议后续在内容审查任务中处理,不计入本批):
    - `MySQL/事务.md:15` `ROOLBACK` → `ROLLBACK`
    - `MySQL/存储过程.md:3` `CREATE PROCEDRE` → `CREATE PROCEDURE`
    - `MySQL/管理.md:2` `SHOW CAHRACTER SET;` → `SHOW CHARACTER SET;`
    - `SQL语句/DDL数据定义.md:17` `SHOWTABLES;` → `SHOW TABLES;`
    - `SQL语句/DML数据操作.md:7` `INSERT INTO表名` → `INSERT INTO 表名`
